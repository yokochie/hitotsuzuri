# ひとつづり（Hitotsuzuri）

macOSの「写真」アプリからアルバムを1つ選び、自分で選んだ4枚を使って記事を作る、macOSネイティブアプリです。本文と画像を出力し、noteへの手動での受け渡しを支援します。

## できること

- 写真アプリ内のフォルダを複数指定し、サブフォルダを含めてアルバムを探す。
- 1つのアルバムから写真を4枚選び、使用する順序を決める。
- 記事の本文・日付・撮影情報を編集し、下書きを手動で保存・再開する。
- 記事をプレビューし、本文をコピーする。
- 記事と画像4枚をまとめて出力し、出力先をFinderで開く。

出力先には、記事ごとのフォルダ内に次のファイルを作成します。

```text
article.md
manifest.json
images/
  01.jpg
  02.jpg
  03.jpg
  04.jpg
```

画像は長辺2560px以下のJPEGとして出力します。小さい画像は拡大せず、向きを画素に反映し、元画像の位置情報等のメタデータを引き継がない形式で生成します。

写真ライブラリ内の写真やアルバムは変更しません。画像取得のための通信もアプリから要求しません。noteへの投稿は、本文の貼り付けと画像の手動アップロードで行います。

## 開発状況

Phase1のアルバム・写真選択に続き、Phase2の記事編集・下書き・出力を実装しています。Phase2の変更は[PR #2](https://github.com/yokochie/hitotsuzuri/pull/2)で統合前の確認を進めています。

現在、下書き復帰や出力後に写真が「画像の取得待ち」のままになり、再試行しても表示されない問題を修正中です。記事を開く際の保存先アクセスエラーは別の修正として、CIと本人のMacで確認済みです。

リール動画生成、アルバムのランダム選択、週次の自動実行・通知、生成AIによる文章補助、noteへの自動投稿は未実装です。原点の要望や将来の設計案と、現在の実装範囲を分けて扱っています。

## 起動する

開発環境はXcodeを使用します。プロジェクトのmacOS Deployment Targetは27.0、Swift言語設定は6.0です。現在の開発・CIはXcode27系を使用しています。

1. `Hitotsuzuri.xcodeproj` をXcodeで開きます。
2. Schemeを `Hitotsuzuri`、実行先を `My Mac` にします。
3. 必要に応じてSigningのTeamを自分の環境に合わせ、Runで起動します。
4. 写真へのアクセスを許可し、対象フォルダ・アルバム・写真4枚を選びます。
5. 記事を開き、本文を編集して保存します。出力時は保存先フォルダを選びます。

通常利用ではテスト用fixtureの起動引数・環境変数を設定しないでください。下書きは手動保存です。未保存の編集を残して別の画面へ移るときは、保存するか確認します。

iCloud等にのみ存在する写真は、表示できても出力用の画像を取得できない場合があります。取得できないときは写真アプリで対象写真を開き、読み込み完了後に再試行してください。ただし、現在修正中の「取得待ち」表示は、写真のローカル可用性とは別の問題として調査しています。

## 検証する

通常の自動検証は[GitHub Actions](.github/workflows/verify.yml)で行います。Coreテストと起動スモークの成功後に、機能UIテストを2つのジョブで並列実行します。最終チェックの `native` はCore・スモーク・両UIジョブの成功を確認します。UIの分割対象に追加漏れや重複があれば検証を失敗させます。カバレッジを含む従来の一括検証は、必要に応じて `bash scripts/verify-native.sh --functional` で実行できます。性能測定と、実写真・OSの保存先選択・noteへの受け渡し等の本人確認は別に扱います。

同じ目的のローカル試験を重複させず、必要なときにリポジトリのルートから対象を指定して再現します。例えば、表示画像の部品テストは次で実行できます。

```bash
bash scripts/verify-native.sh ArticleImageTests ArticlePreviewRetryTests ArticleResourceTests
```

自動UI試験は合成画像と試験所有の保存領域を使います。実写真や通常の保存データを使った確認の成功を、自動試験の結果だけで代用しません。

## GitHubでの変更管理

`main` への変更はPRを通し、GitHub Actionsの `native-core` と `native` の成功、最新のmainへの追従、レビュー会話の解決を必須にしています。管理者にも適用し、force pushとmainの削除は禁止しています。個人開発のため他者の承認件数は要求せず、統合はsquash mergeに限定します。マージ後の作業ブランチは自動削除します。

Dependabotの脆弱性通知と修正PRを有効にしています。[Dependabot設定](.github/dependabot.yml)では、GitHub Actionsの更新を毎週月曜9時（日本時間）に確認し、1つのグループにまとめます。定期更新設定は、このファイルがmainへ統合された後に有効になります。

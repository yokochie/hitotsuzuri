# ひとつづり — 原点の要望

## この文書の目的

「何を実現するためにこのアプリを作るのか」を、設計や実装方法から切り離して残す。AI-DLCでの要件確認や、開発中の優先順位の判断に使う。

会話で確認できた最初の要望を中心に、その後に決まった方針と追加で検討している内容を区別して記載する。技術的な設計案や、アシスタントからの提案すべてを確定要件として扱わない。

## 1. やりたいこと

macOSの「写真」アプリで管理している写真から、毎週、アルバムを1つ選び、そのアルバムの写真を自分で4枚選ぶ。

選んだ4枚を使って、noteの記事とリール用動画を作りたい。

## 2. 現在の写真管理

- 写真はmacOSの「写真」アプリで管理している。
- アルバムは1日ごとに作っている。
- アルバムは写真アプリ内のフォルダで整理している。
- フォルダの下に、さらにフォルダが存在することがある。
- アルバム名には、場所、機材、フィルム、企画名、人物名、撮影日などが含まれる場合がある。ただし、すべての名前に同じ情報が含まれるとは限らない。

アルバム名の実例：

```text
御代田 PENTAX 6x7 Portra 160@260913
情景ポートレートShinya写真教室 白川うみ 寺尾彗@260927
```

ここでいうフォルダは、Finder上の画像ファイルのフォルダではなく、写真アプリ内のアルバムを整理するフォルダを指す。

## 3. 最初の要望

チェックは2026-11-04のユーザーによるPhase 1実装完了報告に基づく。

### 3.1 対象範囲を指定したい

- [x] アルバムを探す対象として、写真アプリ内のフォルダを指定できる。
- [x] 対象フォルダは複数指定できる。
- [x] 指定したフォルダ自身だけでなく、その下のサブフォルダにあるアルバムも対象になる。

### 3.2 アルバムを選んでから写真を選びたい

- [x] 最初に対象アルバムを1つ選ぶ。
- [x] 次に、そのアルバムの中から写真を4枚選ぶ。
- [x] どの写真を使うかは自分で決める。

アルバム選択と写真選択は別の操作であり、複数アルバムの写真を混ぜて4枚選ぶことは最初の要望には含まれていない。

### 3.3 選んだ4枚を発信につなげたい

- [ ] 選んだ4枚を使ってnoteの記事を作れる。
- [ ] 選んだ4枚を使ってリール用動画を作れる。

noteへの直接投稿、文章のAI生成、動画の演出や音楽の仕様は、最初の要望では指定されていない。「作りたい」という目的と、投稿・生成の自動化の範囲は分けて決める。

### 3.4 毎週続けたい

- [ ] この一連の作業を毎週行える。

「毎週行いたい」は利用頻度の要望であり、定期実行や通知の導入までが最初から指定されていたわけではない。

## 4. 望む一連の流れ

1. 対象にする写真アプリ内のフォルダを複数指定する。
2. 指定フォルダとサブフォルダの中から、アルバムを1つ選ぶ。
3. そのアルバムから、自分で写真を4枚選ぶ。
4. 選んだ4枚を使ってnoteの記事を作る。
5. 同じ4枚を使ってリール用動画を作る。
6. この流れを毎週繰り返す。

## 5. その後に決まった方針

### アプリとリポジトリの名称

| 項目 | 名称 |
|---|---|
| アプリ表示名 | ひとつづり |
| リポジトリ名 | `hitotsuzuri` |
| Xcodeプロジェクト名 | `Hitotsuzuri` |
| Swiftのアプリ型名 | `HitotsuzuriApp` |

旧称はPhotoStory。現在の文書・実装では「ひとつづり」を使用する。

### 実装・開発の方針

- SwiftUIによるmacOSネイティブアプリとして作る。
- AI-DLCのフレームワークに従って開発を進める。
- ドキュメントはObsidianで管理できるMarkdownにする。
- 段階的に開発する。Phase 1はアルバムと写真の選択、Phase 2はnote記事作成支援、その後はリール動画生成と週次運用を扱う。

2026-11-04時点のユーザー報告ではPhase 1完了、Phase 2実行中。この文書は実装状況を検証した報告書ではなく、要望の記録である。

## 6. 追加で検討していること：アルバムのランダム選択

Phase 2の実行中に、「アルバムをランダムに選ぶ機能は入っているか」という確認があった。従来の設計書には含まれていなかった。

アルバムのランダム選択は、追加で要件を確定する候補として記録する。導入が承認済み、または実装済みであるとは扱わない。

会話で提示された仕様案：

- 指定した複数フォルダとサブフォルダ配下からアルバムを抽選する。
- 写真が4枚以上あるアルバムを対象にする。
- 抽選結果を表示し、引き直せるようにする。
- 写真4枚は自分で選ぶ。
- 将来、制作済みアルバムや最近選んだアルバムを除外できるようにする。

実装前に、導入する範囲、抽選対象、候補がない場合の動作を確認する。写真の自動選択へ要望を広げない。

## 7. 設計判断で守りたいこと

以下は、原点の要望から導かれる判断の基準である。

- 写真アプリでのフォルダ整理を活かし、対象範囲を自分で決められること。
- アルバムを選ぶ段階と、4枚の写真を選ぶ段階が分かれていること。
- 写真4枚の最終的な選択は自分で行えること。
- 同じ4枚を記事と動画の両方に利用できること。
- 毎週の作業として繰り返せること。

保存形式、画像サイズ、動画の尺、通知、履歴などは、この目的を実現するための設計事項である。変更が必要な場合は目的との整合性を確認する。

## 8. この文書で確定しないこと

以下は最初の要望だけでは確定できないため、各Phaseの要件・設計で決める。

- アルバムを手動で選ぶか、ランダム選択も提供するか。
- 記事のテンプレートと文章生成の有無。
- noteへの受け渡し・投稿方法。
- 動画の縦横比、解像度、表示時間、トランジション、テロップ、BGM。
- 選択順の並べ替えと記事・動画への反映方法。
- 制作履歴、制作済み判定、リマインダーの範囲。
- 公開・投稿操作をアプリ内から行うか。

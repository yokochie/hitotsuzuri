# Phase2 操作の流れ

## 入力と対象
`../intent-capture/intent-statement.md`、`../scope-definition/scope-document.md`、`../scope-definition/intent-backlog.md`、本段階 `rough-mockups-questions.md` に基づく。画面は `wireframes.md` のW1〜W5に対応する。利用者は本人。Phase2限定・通信禁止を維持し、手動保存を採用する。

## 記事を開く・再開する
1. W1の確定済み4枚から「記事を作る／記事を再開」を選ぶ。または「記事」メニューから同じ確定済み選択の記事を開く。
2. 下書きがなければ編集開始、あれば保存済み内容をW2へ復元する。既存下書きの読込失敗を、新規作成として上書きしない。
3. 未確定なら4枚の選択・確定を案内する。画像取得不能でも番号と既存文章を失わず、写真アプリで事前取得するよう案内する。

成功：同じ入口が同じ確定済み選択の下書きへ到達する。履歴一覧や動画画面を追加しない。

## 編集・保存・プレビュー
1. W2で左の番号付き4枚と右の本文フォームを見比べる。狭幅ではW2Nの縦並びで操作する。
2. タイトル・導入・写真ごとの文章・結びを編集し、日付候補の確認・修正・削除、撮影情報の手動入力を行う。
3. 変更後は未保存を表示する。「下書きを保存」で保存中へ進み、完了後のみ保存済みへ変える。自動保存は行わない。
4. 保存失敗なら入力を保持し、理由と再試行を示す。正常に保存できた下書きは再起動後の再開対象となる。
5. W3へ切り替えて記事の順序と内容を確認し、W2へ戻っても入力を保つ。プレビューをnote上の完成表示と保証しない。

成功：本人の文章と写真の対応を保持した下書きを保存・再開できる。

## 未保存で離れる
1. 戻る・閉じる・終了・別対象への切替時に未保存ならW4を表示する。
2. 「保存して閉じる」は成功後に閉じる。保存失敗なら編集を保って閉じない。
3. 「保存せず閉じる」は本人が明示した未保存変更だけを破棄し、旧保存済み下書きを消さない。
4. 「編集を続ける」は入力を維持してW2へ戻る。

成功：明示的な破棄以外で未保存の入力を黙って失わない。強制終了・異常終了で未保存分が回復することは保証しない。

## 書出しとnoteへの受渡し
1. W2またはW3から「記事と画像を書き出す」を実行し、保存先を選ぶ。選択を取り消したら編集に戻る。
2. 開始時の写真順・本文等を固定し、W5に進捗とキャンセルを表示する。重複開始を防ぐ。
3. 画像4枚と本文がそろった成功時のみ完了を表示する。既存成果物は上書きしない。
4. 「Finderで開く」でその成果物フォルダを開き、「本文をコピー」で文章をコピーする。Finder操作自体の失敗は成果物の書出し結果と区別する。
5. 本人がnoteの編集画面へ本文を貼り付け、画像を手動で挿入する。アプリから投稿しない。

失敗分岐：写真の取得不能は事前ダウンロード、権限や容量の問題は原因の解消・保存先の再選択を案内する。取消・失敗で不完全な出力を成功扱いせず、当該処理の一時出力を片付ける。下書きと過去の成功成果物を保ち、再試行できる。

成功：順序の一致した記事と4枚を、本人がnoteの下書きへ手動で移せる。画像用取得は通信を要求しない。

## 画面遷移の概要
W1または記事メニュー → W2/W2Nの記事編集 ↔ W3のプレビュー → 保存先選択 → W5の進捗 → 成功結果 → Finder・本文コピー → noteへの手動受渡し。

未保存で離れる操作はW4へ分岐し、保存成功・明示破棄・編集継続のいずれかへ戻る。取得不能・保存失敗・出力失敗・取消はそれぞれの案内へ分岐し、文章と旧成果物を保持する。

## 情報・操作上の注記
全画面に見出しと現在状態を置き、主な領域とキーボード入口は `wireframes.md` に記載する。写真番号とフォーム番号を合わせ、長い名称・文章と狭い幅でも操作を隠さない。VoiceOverの追加設計・検証は本人の修正依頼により対象外。詳細な外観・保存と出力の順序・日付規則等は後続で確定する。

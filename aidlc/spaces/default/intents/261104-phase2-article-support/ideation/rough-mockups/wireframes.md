# Phase2 画面のたたき台

## 入力と位置付け
`../intent-capture/intent-statement.md`、`../scope-definition/scope-document.md`、`../scope-definition/intent-backlog.md` と、本段階 `rough-mockups-questions.md` の確認済み回答を入力とする。以下は構造を確認する低精度の画面案であり、実装・実機検証済みではない。詳細寸法・色・保存方式は後続で決める。

本人はQ1で入口の両方、Q2で左右配置、Q3で手動保存を選択した。要約の修正依頼によりPhase2のVoiceOver追加設計・検証は対象外。キーボード操作と見えるラベル、状態を文字で伝える方針は残す。以下の見出し・領域の注記は情報整理とキーボード操作のためのもので、VoiceOver要件を追加するものではない。

## 情報の構成
| 層 | 内容 |
|---|---|
| 入口 | 既存の選択確定画面と専用の「記事」メニュー |
| 編集 | 元アルバム、順序付き4枚、日付候補、撮影情報、タイトル・導入・写真ごとの文章・結び |
| 確認 | 編集／プレビューの切替、保存状態 |
| 受渡し | 本文コピー、記事と画像の書出し、結果、Finder表示 |

## W1 選択確定後の入口
| 位置 | 表示・操作 |
|---|---|
| 上部 | 既存のアルバム名と「選択済み4枚」 |
| 中央 | 確定済み4枚を1〜4の番号付きで表示 |
| 操作 | 下書きなしは「記事を作る」、同じ確定済み選択の下書きありは「記事を再開」 |
| メニュー | 「記事」→「記事を作る／再開」。画面のボタンと同じ選択・下書きを開く |

確定済み選択がない場合は「先に写真4枚を選んで確定してください」と表示し、記事を開く操作を無効にする。取得中はその状態を示す。参照切れ・読込失敗を「下書きなし」と誤認して上書きしない。

操作注記：h1相当は選択結果、headerはアルバムと状態、mainは4枚、navは記事メニュー。キーボード入口は記事ボタンまたはメニュー。閉じた後は起点へ戻る。

## W2 記事編集・広い画面
| 上部共通 | 内容 |
|---|---|
| 見出し | 「記事を編集」、元アルバム名（長い場合は折返し）、編集／プレビュー切替 |
| 保存状態 | 「未保存の変更があります」「保存中」「保存済み」「保存できませんでした」のいずれか |

| 左の写真領域 | 右の編集フォーム |
|---|---|
| 1〜4の順序付きプレビュー | タイトル、導入 |
| 写真番号と取得状態 | 写真1〜4それぞれの文章。番号を写真と一致させる |
| 取得不能時も番号と対応を維持 | 結び |
| 写真アプリで事前ダウンロードする案内 | 撮影日候補、確認・変更・削除。候補を確定した事実と混同しない |
| 取得中の表示 | 場所・機材・フィルム・人物名の手動入力 |

| 下部の操作領域 | 内容 |
|---|---|
| 保存 | 「下書きを保存」 |
| コピー | 「本文をコピー」、成功時「本文をコピーしました」 |
| 書出し | 「記事と画像を書き出す」→保存先の選択 |
| 戻る | 選択画面へ戻る。未保存ならW4へ |

本文の自由編集を優先し、入力済みの文章をテンプレートや日付候補の更新で勝手に置き換えない。写真の並べ替え・差替えをこのたたき台へ追加せず、確定順との対応を保つ。文章の空欄・長文・改行は表示を壊さず、必須入力の詳細は要件で決める。保存失敗時は入力を保持して同じ保存操作で再試行する。

操作注記：h1相当は記事編集、h2は写真・本文・撮影情報、h3は各写真。headerは元アルバムと切替、mainは左右の内容、footerは保存・コピー・書出し。キーボード順は切替→写真領域の必要操作→フォーム→下部操作とし、複数行入力内のTab等は既存macOSの慣行に沿って後続仕様で具体化する。色だけで保存失敗を表さない。

## W2N 記事編集・狭い画面
上から「見出しと切替 → 番号付き4枚 → 本文フォーム → 撮影情報 → 保存・コピー・書出し」の順に縦へ並べる。縦スクロールで全項目と操作へ到達できる。幅変更で入力・写真対応・保存状態を消さない。左右レイアウトとの切替境界は内容を使って後続で決め、ここでは固定値を約束しない。

操作注記：h1〜h3と領域はW2と同じ。キーボード順を視覚順に合わせ、スクロールの外にある操作にも到達できるようにする。固定フッターが本文やフォーカスを隠さない。

## W3 記事プレビュー
上部に「プレビュー」「編集へ戻る」と保存状態。本文は「タイトル → 導入 → 写真1と文章 → 写真2と文章 → 写真3と文章 → 写真4と文章 → 結び」。日付・撮影情報を本文へどう反映するかは要件で確定する。note上の最終表示と同一であるとは表示しない。表示中の下書きを確認し、未保存ならその状態を残す。

写真が一部取得できなくても文章と番号を残し、「写真3を取得できません」等の案内を表示する。プレビューの表示成功を、記事用画像の取得成功や書出し成功とは扱わない。編集へ戻っても入力を保持する。

操作注記：h1相当は記事タイトル、mainは記事の読み順、headerは切替と保存状態、footerは本文コピー・書出し。キーボード入口は編集へ戻る操作。写真は番号と対応を文字でも示す。

## W4 未保存で離れる際の確認
「未保存の変更があります。保存してから閉じますか？」に対して「保存して閉じる」「保存せず閉じる」「編集を続ける」を表示する。破棄は本人が明示的に選んだ場合だけ。保存失敗時は閉じず、本文を保持して理由と再試行を示す。メニュー経由で別の編集対象を開く場合も、現在の未保存入力を黙って失わない。アプリ終了時も同じ保護を計画する。

操作注記：h1相当は確認の見出し、mainは対象と説明、footerは3操作。キーボードで全選択肢に到達でき、キャンセルで編集に戻る。確認終了後は適切な編集操作へフォーカスを戻す。

## W5 書出し中・結果
| 状態 | 表示 | 操作・保護 |
|---|---|---|
| 保存先選択 | 利用者がフォルダを選ぶ | 選択取消は失敗や成功と混同せず編集へ戻る |
| 実行中 | 「画像2/4を書き出しています」等、処理中と分かる進捗 | 「キャンセル」。二重開始を防止し、処理中内容を固定する |
| 成功 | 「記事と画像4枚を書き出しました」、保存先 | 「Finderで開く」「本文をコピー」「編集へ戻る」 |
| 取得不能 | 該当する写真番号と事前ダウンロードの案内 | 下書きを残す。通信せず、準備後に再試行 |
| 失敗 | 原因に応じた日本語案内。保存先権限・容量不足等を区別 | 「再試行」「編集へ戻る」。旧成果物を上書きしない |
| 取消 | 「書き出しをキャンセルしました」 | 成功表示とFinder完了導線を出さず、当該処理の不完全出力を片付けて編集へ戻る |

4枚と本文がそろった場合だけ成功とする。Finder表示の失敗は書出し失敗とは分けて保存先と再操作を案内する。未保存の本文を出力するか保存を先に要求するかは要件で決めるが、画面にない古い本文を無言で出力しない。

操作注記：h1相当は書出し状態、mainは進捗・結果・失敗理由、footerは取消・再試行・Finder等の現在有効な操作。キーボード入口は実行中の取消または結果の操作。状態遷移で入力の焦点を不必要に奪わない。

## 状態の網羅と後続確認
空の選択・下書きなし、読込中、正常編集、未保存、保存中、保存失敗、写真の一部取得不能、長文・長名、書出し中・成功・失敗・取消を上記に含める。実際のキーボード到達性・ウインドウ幅・保存先アクセス・note受渡しは実装後の確認事項。VoiceOver追加設計・検証は今回の対象外とする。

# Phase2のリスク・前提・課題・依存

入力: `../intent-capture/intent-statement.md`、`feasibility-questions.md`。コードと前回記録の根拠は `feasibility-assessment.md` を参照する。未検証事項を成功に読み替えない。

## Risks
| ID | リスク | 影響 | 対応と解消証拠 |
|---|---|---|---|
| R1 | 表示用画像は512px。記事用画像で編集・回転・色が保持されない | 高：成果物品質 | 実画像1枚の書出しを先に検証し、4枚統合前に記録する |
| R2 | ローカルの表示画像があっても必要解像度の画像を取得できない | 高：書出し不能 | 通信禁止のまま取得不能を案内し、写真アプリで事前取得後の再試行を確認する |
| R3 | 下書き追加・形式変更で既存選択を読めない、正常データを失う | 高：データ損失 | 旧schemaVersion 1のfixtureと破損・未知版・途中書込のテスト。引継ぎ方式を計画で本人確認 |
| R4 | 保存先権限・容量不足・取消で半端な成功成果物が残る | 高：誤った成功表示 | 書出し失敗・取消・再出力・既存成果物保護の統合試験とSandbox実機確認 |
| R5 | 写真アプリの編集・位置情報除去・noteでの受渡しを自動試験だけで保証した扱いにする | 高：確認漏れ | 実画像と本人のnote下書きで確認。未確認は明示して保持 |
| R6 | Phase1の速度未達・既知操作問題・未確認を今回の変更で見落とす | 中：既存品質の悪化 | 既存試験を変更前後で再実行し、既知問題と新規回帰を区別する |

## Assumptions
新しい本人側の制約を推測して置かない。画像書出しや移行の成立性は仮定して確定せず、未検証課題I2〜I4として管理する。

## Issues
| ID | 現状の課題 | 所有・対応先 | 完了条件 |
|---|---|---|---|
| I1 | Phase1記録に速度条件未達・子フォルダ折畳みの既知問題・実機未確認・横断追跡未被覆が残る | 実装担当が影響調査し、優先順位の変更は本人判断 | 既存の受入記録を保持し、Phase2の回帰や阻害要因と区別した記録 |
| I2 | Phase2の記事用画像書出しは未検証 | 実装担当、要件・実装計画 | 実画像の検証証拠と本人確認項目が揃う |
| I3 | 下書きと既存選択の互換性・保存方式は未確定 | 設計担当、後続の既存実装調査・設計 | モデル差分・移行対象・旧データ読込試験を計画に記載 |
| I4 | Sandboxで利用者指定先への書出し権限は未検証 | 実装担当、画像書出しの技術検証 | 権限を含む設定差分と成功・拒否・取消の実機結果 |
| I5 | Phase1のCI省略例外と現行規約の統合前CIを区別する必要がある | 計画担当、品質担当 | Phase2に適用する実行環境・対象・証拠を計画し、例外が必要なら本人判断を受ける |

## Decisions
本人は追加連携なし、追加の勤務先等の制約なし、固定期限・特別な予算枠・停止事情なし、有料追加を前提にしないと回答した（本段階Q1〜Q3）。画像取得の通信禁止とPhase2限定の範囲を変更しない。

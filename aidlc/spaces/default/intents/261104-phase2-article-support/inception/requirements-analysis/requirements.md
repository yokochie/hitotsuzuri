# Phase2 要件

## Intent Analysis
本人がPhase1で選んだ4枚と文章を整え、noteの下書きへ手動で移す週次制作を支援する。下書きと元写真の取得可否を分離し、文章を失わず、成功した成果物だけを利用者へ渡す。

## Functional Requirements
全FRはMust。入力に不正や失敗がある場合も、過去の正常な選択・下書き・成果物を黙って上書きしない。

| ID | 要件 | 正常時の判定 | 失敗・境界時の判定 | 根拠 |
|---|---|---|---|---|
| FR1 | 確定済み選択から制作記事を開始し、選択ID、アルバムID・当時の名称、順序付き写真ID4件、作成・更新情報と記事の識別情報を保持する | 異なる4枚を同じ順序で記事へ対応させ、元選択を変更しない | 未確定・重複ID・4枚未満等の不正選択では開始しない。原因を表示し旧記事を保護 | SC1、既存CommittedSelection |
| FR2 | 選択確定後の「記事を作る／記事を再開」と「記事」メニューを同じ記事操作へ接続する | 同じ確定済み選択の下書きがあれば再開し、なければ作成する | 読込失敗を下書きなしと扱わない。二重起動で同じ下書きを意図せず複製・上書きしない | 画面Q1、SC1/SC2 |
| FR3 | 同じアルバム・同じ順序の4枚を再確定した場合、新規作成か既存下書き再開かを本人へ確認する | 新規は旧記事を保って別記事、再開は選んだ既存記事の文章を保持 | 候補が複数なら名称・更新日時等で区別して選ぶ。取消は何も変えない。写真順が違う候補を同じ組として自動再開しない | 本段階Q1 |
| FR4 | 記事タイトル・導入・各写真の文章・結びを編集し、写真IDに対応させる | 改行、日本語、絵文字、引用符等を保存・復元でき、文章は写真番号と対応する | 空欄を許容し撮影事実を補完しない。編集済み本文を初期候補や再読込で上書きしない。長文はスクロールで扱う | SC2、画面案、本段階Q3 |
| FR5 | 下書きを手動保存し、再起動後に復元する。保存状態を未保存・保存中・保存済み・失敗に分ける | 「下書きを保存」の永続化成功後だけ保存済み。自動保存はしない | 保存失敗は入力と旧正常データを保持し再試行可能。保存中の重複開始・古い完了通知で新しい編集を保存済みにしない | SC2、画面Q3 |
| FR6 | 未保存で戻る・閉じる・終了・別記事へ切り替える場合は確認する | 保存して離れる／保存せず離れる／編集継続を選べる | 保存失敗では離れず入力保持。明示的破棄だけ未保存分を捨て、旧保存済み記事は消さない | 画面Q3/W4 |
| FR7 | 元写真の取得・認可・参照状態に依存せず、保存済み文章と撮影情報を開き、編集・保存・コピーできる | 写真の一部取得不能でも下書きを再開できる | 取得不能の写真番号と理由・次の操作を示す。本文を消さず、画像4枚の出力成功は宣言しない | 本段階Q2 |
| FR8 | アルバム名の末尾@とASCII数字6桁を2000〜2099年の撮影日候補とする | @260913は2026-09-13、閏年の有効日を候補化し、年月日として保持 | @260231等の不正日付は補正せず未解析。接尾辞なし・全角数字・後続文字は候補化しない。タイムゾーン変更で日付がずれない | 本段階Q3 |
| FR9 | 撮影日候補は候補と明示し、確認・手動修正・削除できる。場所・機材・フィルム・人物名を手動入力する | 修正・削除を保存し、再開時も維持。手動日付も有効な年月日に限る | 不正入力は項目と修正方法を表示して入力を保持。名前から人物・場所・機材を機械的に確定しない | SC3/SC4、本段階Q3 |
| FR10 | 新規記事では末尾の形式一致した@6桁接尾辞を除いた名前をタイトル候補にし、本文は空欄とする | 日付の妥当性とは独立して形式一致の接尾辞を除く。候補を自由編集できる | 接尾辞なしは元名、除去後空なら空欄。既存記事へ候補を再適用しない | 本段階Q3、初期候補の境界規則 |
| FR11 | 順序付き4枚のプレビューと編集フォームを表示し、編集／プレビューを切り替える | 広幅は左に4枚・右にフォーム、狭幅は縦配置。プレビューはタイトル・導入・写真と文章1〜4・結び・撮影メモの順 | 幅変更・切替で入力・順序を失わず、全入力と保存・出力へ到達可能。プレビューをnote上の最終表示と保証しない | 画面Q2、SC1/SC2 |
| FR12 | コピーは現在の入力を用い、プレーンテキストのタイトル・本文・撮影メモをクリップボードへ渡す | 入力済みの撮影日・場所・機材・フィルム・人物名だけ末尾「撮影メモ」へ含め、空欄は省略 | 未保存なら未保存表示を維持し、コピーで保存済みにしない。写真画像やローカル画像パス・manifestを本文コピーに混ぜない | SC6、本段階Q5 |
| FR13 | 記事と画像の出力前に下書きの保存を求め、成功した保存内容と写真順を固定する | 未保存なら保存・取消を案内し、成功後の内容を出力する | 保存失敗や取消で出力を開始しない。実行中の編集や古い応答でジョブ内容を変えず、重複開始を防ぐ | 本段階Q5、SC8 |
| FR14 | 表示用画像ではなく用途に必要な画像を通信禁止で取得し、現在の編集・回転を反映した静止画JPEGを作る | sRGB、品質0.9、長辺2560px以下、元より拡大しない。HEIF/RAW等は取得可能な編集結果をJPEGへ、Live Photoは静止画へ変換 | 記事用画像取得不能をサムネイルで代用して成功にしない。通信へ切替えず事前取得と再試行を案内。位置情報等の不要な元メタデータをコピーしない | SC5、本段階Q4、通信禁止 |

| FR16 | manifestをローカル管理用として、形式版・記事ID・元選択ID/選択リビジョン・順序付き写真ID・相対画像パス・本文パス・出力日時・出力時の保存内容の識別情報を記録する | 4枚と本文の固定内容を追跡でき、同じ出力内の対応が一致する | manifestはnoteへの本文コピー対象に含めず、外部送信しない。IDや名称をシェル・パス命令として解釈しない | 資料のmanifest提案、本段階Q4/Q5、SC5 |
| FR17 | 取得・書出しの進捗、完了、取消、失敗理由と再試行を表示する | 4枚と記事・manifestが完成した時のみ成功。順序と画像参照を検証して完成扱いにする | 1枚失敗、容量不足、権限喪失、取消は成功にしない。当該ジョブの一時出力を片付け、下書きと旧成果物を保持。片付け失敗も案内し、残存物を成功として表示しない | SC8、画面W5 |

## Non-functional Requirements
全NFRはMust。以下は今回の追加・変更範囲の品質条件。既存Phase1の未達や未確認を合格へ変更しない。

| ID | 条件と判定方法 | 根拠 |
|---|---|---|
| NFR1 | 写真ライブラリを変更せず、記事用を含む全画像要求で通信禁止を設定する。権限なし・取消・失敗でも許可へ切り替えない。境界オプションの自動試験と実機オフライン確認で判定 | 目的、制約、team-practices |
| NFR2 | schemaVersion 1の既存選択を読込可能とし、欠損・破損・未知版・I/O失敗を空データと区別する。書込失敗・中断で旧正常データを失わず、未知版を自動上書きしない。fixture・失敗注入・再起動で判定 | SC1/SC2、既存architecture |
| NFR3 | 画像処理・ファイルI/Oで編集画面の無関係な操作を同期的に塞がず、全フレーム等を無制限に保持しない。高解像度画像は4枚全体を無制限並列デコードしない。取得・取消を必ず終端へ収束させる期限と画像メモリ予算の数値・計測条件をNFR Requirementsで確定し、Code Generation前に確認する。既存表示用15秒/256MiBを記事出力の実証値としない | feasibility、CodeKBの表示画像制約 |
| NFR4 | 操作をキーボードで完了でき、狭幅・長い日本語名・長文・改行でも全入力と主要操作へ到達できる。状態は色だけで伝えず文字と見えるラベルを付ける。対象幅・文字条件は後続の画面仕様で数値化し、UI試験と本人確認で判定。VoiceOver追加設計・試験は対象外 | 画面案、team-practices、本人変更 |
| NFR5 | テスト可能な各層でTDDのred-green-refactorを記録し、既存回帰試験を維持する。製品全体の行カバレッジ80%以上、統合前CIの成功を要求する。CI実行先・設定・費用は実装計画で本人確認し、手動試験をCIと呼ばず、未達なら統合完了にしない | team-practices |
| NFR6 | 診断は失敗分類を基本とし、通常ログに写真・本文・写真ID・人物名・場所を出さない。下書き・manifestはローカルに保存し自動送信しない。本文と画像の手動受渡しに必要な表示・成果物は区別する。ログ捕捉・出力検査で判定 | 既存診断境界、通信禁止、個人利用 |
| NFR7 | 実写真の編集・回転・色・位置情報除去、Sandbox保存先、noteへの貼付け・画像手動挿入は本人の実機確認として日本語で結果を残す。自動試験と未確認を混同せず、対象OS・Xcode・署名・再現コマンド・戻し方を手順に明記 | SC5/SC6、team-practices |

## Constraints
- 本人のMacで個人利用する既存macOSアプリ。現行設定はmacOS 27.0・Swift 6.0・Sandbox有効。対応OSを無断で拡大・変更しない。
- 要件と実装計画の本人確認後に実装する。有料追加・固定期限を仮定しない。
- 画像出力は毎回別フォルダ。保存先アクセスは本人の選択に基づき、再起動後の永続アクセスが必要となる場合だけその範囲を設計・確認する。
- 写真順変更・差替えを記事画面へ追加しない。Phase1での確定順を保持し、異なる確定は別の選択として扱う。

## Corner-case Disposition
| 対象 | 条件 | 扱い |
|---|---|---|
| ファイル | 不在・権限拒否・容量不足・途中書込・同名・Unicode・外部変更 | FR5/FR15/FR17、NFR2。保存先のシンボリックリンクや別名で意図外領域へ出ないよう設計で検証する |
| 永続化 | 複数の編集入口・二重保存・古い応答・将来版 | FR2/FR5/FR13、NFR2。単一プロセス内の編集対象を統一し、外部変更は無断上書きせず競合を案内 |
| 文字 | 空欄・空白のみ・長文・絵文字・引用符・Markdown記号 | FR4/FR10/FR12/FR15。空白のみの撮影情報は空欄として省略、自由本文の改行を保持。Markdown画像構文を壊す文字を適切に扱い、任意入力を実行しない |
| 日付 | 閏日・月末・不正日・全角数字・末尾以外・タイムゾーン | FR8/FR9/FR10。自動補正なし、年月日の検証と候補表示 |
| 写真 | 権限取消・削除・iCloudのみ・編集・縦横・HEIF/RAW・Live Photo | FR7/FR14/NFR1/NFR7。取得不能は下書き喪失にしない |
| ジョブ | 中断・取消・二重開始・設定変更・遅い応答 | FR13/FR17/NFR3。固定内容・終端判定・一時出力保護。プロセス異常終了後の一時物の検出・扱いを設計に含める |
| UI | 読込中・空・一部成功・失敗・長名・狭幅・保存前離脱 | FR2/FR6/FR7/FR11/FR17、NFR4 |
| 実行環境 | clean checkout・CI差異・初回・既存データ | NFR2/NFR5/NFR7。ツール未確認を導入済みとしない |
| 認証・複数利用者 | アカウント・テナント・外部API・複数端末同期 | 今回対象外。本人の単一ローカルアプリとOSの写真/ファイル権限を扱う |

## Assumptions & Open Questions
本人の意思決定に関する未回答はない。以下は設計・計画で解決する作業事項であり、成立済みとは仮定しない。
- 記事IDと再確定選択の関連、複数候補・過去下書きを再開する具体的なメニュー導線、保存形式の差分・移行対象と互換性の証拠。
- 記事用画像の取得方式と編集・回転・色変換、保存先権限、一時出力の確定と異常終了からの回復。
- NFR3の期限・画像メモリ予算、NFR4の対象幅・長文条件、CI実行環境の具体案。Code Generation前の計画に未解決のまま持ち込まない。

## Out of Scope
動画・演出・音声、制作履歴一覧画面・候補表示・通知、AI文章補助、note自動投稿・直接連携、外部公開・独自クラウド、画像取得通信、VoiceOver追加設計・検証。下書き選択に必要な最小メニューは記事再開の範囲とし、成果物履歴管理へ広げない。

手動保存前の強制終了・クラッシュで未保存文章の復元は保証しない。写真本体のバックアップ・復元、元写真を失った後の旧出力画像の自動再利用は含めない。Phase1の全既知問題の解消は今回の約束とせず、影響と新規回帰は検証する。

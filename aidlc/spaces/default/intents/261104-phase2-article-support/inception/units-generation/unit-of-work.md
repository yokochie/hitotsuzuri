# Phase2 実装単位

## 入力・構成
`../domain-design/components.md`・`decisions.md`、`../requirements-analysis/requirements.md`、`../user-stories/stories.md`、本段階の確認済み回答と分割計画承認を入力とする。5責務の正本所有を維持し、3つの利用可能な差分にまとめる。全て単一の既存macOSアプリに組み込む。別アプリ・独立サーバー・新しい外部サービスは作らない。

| Unit ID | Directory | 名称 | kind | 配置 | 相対規模 | 依存 |
|---|---|---|---|---|---|---|
| U1 | u1-article-foundation | 最小の記事制作接続 | service | 既存アプリ内の実行可能な最小一式 | L | なし |
| U2 | u2-draft-experience | 下書き編集と再開 | ui | 同じアプリの画面と操作調整 | L | U1 |
| U3 | u3-article-export | 4枚と記事の安全な出力 | library | 同じアプリへ組込む出力・受渡し処理 | L | U1、U2 |

kindは設計成果物の対象を表す。U1は実行可能なアプリ差分、U2は画面中心の差分、U3は独立実行しない出力ライブラリ中心の差分である。U3にも既存画面へ接続する薄い操作の配線は含む。テスト・品質条件は全単位に適用し、kindを理由に必要な業務動作や失敗条件を除外しない。

## U1 最小の記事制作接続
### 範囲・所有
ExistingSelectionの読込境界を使い、ArticleWorkspaceの基礎モデル・記事識別・独立保存を作る。ArticlePresentationの最小記事開始・本文編集・手動保存・再開と、ArticleImages/ArticleDeliveryの最小実画像1枚出力を接続する。各責務の所有はcomponents.mdどおりで、U1という新しい正本は作らない。

### 単独で動く条件
既存アプリから確定済み4枚を引き継ぎ、基本タイトル・本文を手動保存し、再起動後に文章を再開し、本人が選んだ保存先へ記事用の実画像1枚を出力できる。旧schemaVersion 1の選択を破壊しない。文章の再開は画像取得成功に依存させない。最小でも未保存の明示破棄・保存失敗の保護は省略しない。

1枚の技術検証は「画像1枚の検証出力」と明示し、4枚の記事セット成功とは表示しない。後続U2/U3の未実装型を参照せず、実アダプタと最小画面をU1自身で用意する。保存先アクセス・通信禁止・現在の編集/回転とJPEG初期設定・元写真非変更をこの経路で実証する。デモ・検証コマンドはDelivery Planningで確認する。

### 完了証拠・制約
既存選択読込、保存/再開、失敗注入、実画像1枚出力の自動/本人確認を分ける。下書きと出力の契約値を後続へ公開する。TDD・カバレッジ・CI条件と要件の安全境界は維持する。完全な日付フォーム・候補一覧・4枚セットの成果物整合は後続担当と明記する。

## U2 下書き編集と再開
### 範囲・所有
U1のArticleWorkspaceと最小画面を拡張し、ArticlePresentationの利用機能を完成させる。入口2か所、下書き選択、再確定時の新規/再開、全本文欄と撮影情報、日付候補、左右/縦配置、プレビュー、キーボード、手動保存と未保存離脱確認を担当する。記事正本はWorkspaceのまま、日付と本文投影規則はその責務内で実装する。

### 完了証拠・制約
US1.1〜US1.6の利用機能をfixtureで独立試験し、写真取得不能でも文章を扱えること、長名・長文・境界幅、破損/未知版/競合時の保護を確認する。本文コピー用の現在入力からのプレーンテキスト投影はU2、クリップボードへのOS書込と成功表示の最終接続はU3とする。U2では投影と呼出し契約をFakeで検証でき、U3の実装を必要としない。

## U3 4枚と記事の安全な出力
### 範囲・所有
U1の画像取得・保存先・記事出力の基礎とU2の完成本文投影/保存操作を利用し、ArticleDeliveryとArticleImagesの4枚出力経路を完成させる。固定入力、Markdown、manifest、画像4枚、相対参照、毎回別フォルダ、一時生成と成功確定、進捗・取消・失敗・復旧を担当する。クリップボードとFinderの実OS境界、出力前保存と完了結果の画面接続を含む。

### 完了証拠・制約
US1.7/US1.8とUS1.6のコピー実操作を完成させる。1枚でも失敗なら成功にせず、旧成果物と下書きを保護する。正常・失敗・取消でも元写真を変更せず、通信を要求しない。実画像の編集・回転・色・メタデータ、Sandbox、Finder、noteへの手動受渡しは本人確認と自動試験を分ける。

## 共通品質と非対象
全単位でNFR1〜NFR7の担当部分を維持し、部分実装の成功をPhase2全体成功にしない。未決定の期限・メモリ予算・保存技術・APIは後続設計、CI環境と費用は実装計画で確定する。CI条件未達で統合完了としない。VoiceOver追加設計・試験、動画・通知・直接投稿等は対象外。既存Phase1の問題と新規回帰を区別する。

## 境界をまたぐ変更の管理
5責務を単位へ排他的に割当てる方式ではなく、U1が最小契約を作り、依存先を使うU2/U3が責務内の利用機能を拡張する。単位ごとのファイル所有・共有型の変更手順・試験コマンドは計画で具体化する。後続が必要とする契約の形はContract Designで確定し、依存にない型を先取り参照しない。

## 前提
利用者は既に確認済みの本人1種類とする。新しい人物像や関係者は作らない。`../requirements-analysis/requirements.md` と既存機能の調査、`../practices-discovery/team-practices.md` に従う。ストーリーは「本人として、目的を達成するために操作したい」という価値中心の形とし、Given/When/Thenの受け入れ条件を付ける。独立して検証可能・交渉可能・価値あり・見積可能・小さい・試験可能というINVESTの観点で確認する。

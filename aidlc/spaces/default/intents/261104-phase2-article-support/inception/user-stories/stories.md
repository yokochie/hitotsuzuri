# Phase2 利用場面と受け入れ条件

## 入力・共通条件
`../requirements-analysis/requirements.md` のFR1〜FR18・NFR1〜NFR7、`user-stories-questions.md` の確認済み計画に基づく。利用者は `personas.md` のP1（本人）1種類。既存機能の根拠は `aidlc/spaces/default/codekb/hitotsuzuri/business-overview.md`、`component-inventory.md`。進め方は `../practices-discovery/team-practices.md` に従う。

以下のACはGiven（前提）・When（操作・事象）・Then（観測結果）の受け入れ条件。全ストーリーはMust Have。依存は実装時の接続関係で、テストは各場面に必要な選択・下書き・出力先のfixtureを準備して独立に実行できる。下書きや出力の存在は試験成功を意味しない。

## US1.1 記事を開始し、再確定時に作り方を選ぶ
本人として、確定した4枚から記事を開き、同じ4枚を再確定したときは新規か再開か選びたい。既存文章を意図せず置き換えず制作するため。

対応：FR1、FR2、FR3、NFR2。優先度：Must Have。依存：既存選択データ。

- **AC1.1.1** Given 有効な確定済み4枚と下書きなし、When 確定画面の「記事を作る」または「記事」メニューを選ぶ、Then 元選択・当時のアルバム名・写真ID4件と順序を保持した記事が開き、元選択は変わらない。
- **AC1.1.2** Given 同じ確定済み選択に保存済み下書きあり、When どちらの入口から開く、Then 同じ記事と文章が復元され、二重操作でも意図しない複製は作らない。
- **AC1.1.3** Given 同じアルバムと同じ順序の4枚を新しい選択IDで再確定、When 記事を開く、Then 新規／既存下書き再開／取消を選べる。新規は旧記事を保持し、再開は選んだ文章を保持し、取消は何も変えない。
- **AC1.1.4** Given 再開候補が複数、When 選択する、Then 名称・更新日時等で区別できる。順序が異なる4枚を同じ候補として自動再開しない。
- **AC1.1.5** Given 未確定・4枚未満・重複IDまたは下書き読込失敗、When 記事開始を試す、Then 開始不能の理由を表示し、失敗を下書きなしとして既存データを上書きしない。

INVEST：記事開始という価値で独立し、選択fixtureで試験可能。UI詳細と記事関連付け方式は設計で選べる。複数候補の導線を含む中程度の規模で、正式Unitではない。

## US1.2 下書きを編集し手動保存する
本人として、写真に対応する文章を編集・保存・再開したい。週次制作を途中で中断しても保存済み文章を続けられるため。

対応：FR4、FR5、NFR2、NFR6。優先度：Must Have。依存：US1.1の記事識別。

- **AC1.2.1** Given 記事を編集中、When タイトル・導入・写真ごとの文章・結びを入力する、Then 写真IDと番号に対応した文章と未保存状態を保持し、空欄・改行・日本語・絵文字・引用符・長文を壊さない。
- **AC1.2.2** Given 未保存変更あり、When 「下書きを保存」を実行する、Then 保存中を表示し、永続化成功後のみ保存済みとなる。入力だけでは自動保存しない。
- **AC1.2.3** Given 保存成功した下書き、When アプリを再起動して開く、Then 文章・写真対応・撮影情報を復元する。
- **AC1.2.4** Given 容量不足・権限拒否等の保存失敗、When 保存する、Then 入力と旧正常データを保ち、失敗理由と再試行を示す。重複保存・古い完了が新しい編集を保存済みにしない。
- **AC1.2.5** Given 旧形式選択・破損・未知版・外部変更のいずれか、When 読込・保存する、Then 正常な旧選択は読め、破損・未知版・I/O失敗は空データと区別し、自動破棄や無断上書きをしない。通常ログに本文・写真ID・人物名・場所を出さない。

INVEST：保存・再開という価値でまとまり、実ファイルと失敗注入で独立試験可能。保存方式は交渉可能。複雑な競合条件を明示して見積り材料とする。

## US1.3 未保存のまま離れるときに判断する
本人として、未保存変更のある画面を離れる前に保存するか選びたい。作成中の文章を黙って失わないため。

対応：FR6、NFR2。優先度：Must Have。依存：US1.2の保存結果。

- **AC1.3.1** Given 未保存の文章あり、When 戻る・閉じる・終了・別記事への切替を行う、Then 保存して離れる／保存せず離れる／編集継続の確認を出す。
- **AC1.3.2** Given 確認画面、When 保存して離れるを選ぶ、Then 保存成功時のみ離れ、失敗時は入力を保持して閉じない。
- **AC1.3.3** Given 確認画面、When 保存せず離れるを明示選択する、Then 未保存分だけを破棄し、旧保存済み記事は残す。
- **AC1.3.4** Given 確認画面、When 編集継続または取消を選ぶ、Then 入力を保って編集へ戻る。キーボードでも全選択肢へ到達できる。

INVEST：離脱時の保護という小さい価値。変更あり状態と保存Fakeで試験可能。異常終了で未保存分を復旧する追加機能は含めない。

## US1.4 写真が取得不能でも文章を再開する
本人として、写真が消えた・許可されない・ローカルにない場合も文章を開きたい。下書きを失わず作業を続けるため。

対応：FR7、NFR1、NFR2。優先度：Must Have。依存：US1.2の保存済み下書き。

- **AC1.4.1** Given 保存済み文章と撮影情報、元写真の一部または全てが取得不能、When 下書きを開く、Then 文章を編集・保存・コピーでき、欠けた写真の番号と理由を表示する。
- **AC1.4.2** Given iCloud上のみ等で記事用画像をローカル取得できない、When 取得する、Then 通信を要求せず写真アプリでの事前取得と再試行を案内する。表示用画像だけの取得で記事出力成功とはしない。
- **AC1.4.3** Given 取得不能写真あり、When 4枚書出しを試す、Then 成功結果を出さず、下書き・旧成果物を保つ。
- **AC1.4.4** Given 写真を事前取得して再試行可能になった、When 再試行する、Then 最新の結果だけを反映し、文章や写真順を変更しない。権限取消・削除・取消でも通信許可へ切り替えない。

INVEST：写真取得から文章の継続を独立させる価値。取得不能Fakeで他の写真操作から独立試験可能。復元構造の改修範囲は設計で見積もる。

## US1.5 日付候補を確認し撮影情報を入力する
本人として、アルバム名からの日付候補を確認し撮影情報を手動で整えたい。事実を自分で判断して記事へ記載するため。

対応：FR8、FR9、FR10、NFR2。優先度：Must Have。依存：US1.1の記事と元名称、US1.2の保存。

- **AC1.5.1** Given 名前末尾が@260913、When 新規記事を作る、Then 2026-09-13を候補と示す。@000229は有効、@260231は自動補正せず未解析とする。
- **AC1.5.2** Given 接尾辞なし・全角数字・末尾以外の@6桁、When 解析する、Then 日付候補を作らない。形式一致の末尾接尾辞だけをタイトル候補から除き、不正日付でも文字列の除去規則は同じ。除去後空なら空欄。
- **AC1.5.3** Given 日付候補あり、When 確認・手動変更・削除して保存する、Then 年月日の値を保持し、タイムゾーン変更後も日付がずれない。不正な手動日付は入力を残して修正案内する。
- **AC1.5.4** Given 場所・機材・フィルム・人物名の入力、When 保存・再開する、Then 本人の値を保持し、名前から情報を勝手に確定・創作しない。
- **AC1.5.5** Given 新規記事または編集済み記事、When 初期化または候補情報を更新する、Then 新規本文は空欄、タイトルは候補とし、編集済み本文・タイトルを無断置換しない。

INVEST：入力補助として独立した価値。日付境界の純粋テストと保存試験が可能。日付・自由入力を細分化する余地を残す。

## US1.6 プレビューと本文コピーで記事を確認する
本人として、4枚と文章を見比べ、現在の本文をコピーしたい。noteへ移す前に記事を整えるため。

対応：FR11、FR12、NFR4、NFR6。優先度：Must Have。依存：US1.2/US1.5の入力。

- **AC1.6.1** Given 記事編集中、When 広幅・狭幅へ変更する、Then 左写真/右フォームまたは縦並びで、全入力と保存・出力へキーボード到達できる。長名・長文・切替で入力を失わない。
- **AC1.6.2** Given 4枚と文章、When プレビューへ切り替える、Then タイトル・導入・写真と文章1〜4・結び・撮影メモの順に表示し、写真番号を対応させる。note上と同一表示とは案内しない。
- **AC1.6.3** Given 未保存変更と撮影情報あり、When 本文をコピーする、Then 現在の入力をプレーンテキストで渡し、入力済み項目だけ撮影メモへ含める。写真画像・ローカル画像パス・manifestを混ぜず、未保存状態を維持する。
- **AC1.6.4** Given 空白のみの撮影項目やMarkdown記号・絵文字・改行を含む本文、When コピー・表示する、Then 空の撮影項目は省略し、本文の文字・改行を保持して任意入力を実行しない。色だけで状態を示さない。

INVEST：確認してコピーするという利用価値。本文投影とUI試験で独立検証可能。対象幅・長文条件は後続の画面仕様で数値化する。

## US1.7 保存した記事と4枚を安全に出力する
本人として、保存した記事と編集済み4枚を一式で書き出したい。前回の成果物を守りながらnoteへ移せる材料を得るため。

対応：FR13〜FR17、NFR1、NFR2、NFR3、NFR6。優先度：Must Have。依存：US1.2/US1.5の保存、記事用画像の早期検証。

- **AC1.7.1** Given 未保存変更あり、When 書出し開始する、Then 保存を求め、保存成功した内容と写真順・設定を固定する。保存失敗・保存取消・出力先選択取消ではジョブを開始しない。
- **AC1.7.2** Given ローカル取得可能な編集済み縦横画像・HEIF/RAW・Live Photoの静止画、When 出力する、Then 現在の編集と回転を反映したsRGB JPEG・品質0.9・長辺2560以下・元より拡大なしとなり、位置情報等の不要メタデータをコピーしない。通信や表示用512pxでの代用をしない。
- **AC1.7.3** Given 有効な保存先、When 同じ記事を複数回出力する、Then 毎回別フォルダのarticle.md、manifest.json、images/01.jpg〜04.jpgがそろい、Markdown相対参照が実在する順序付き画像へ結ぶ。既存成果物を上書きしない。
- **AC1.7.4** Given 固定した記事・選択・出力内容、When manifestを確認する、Then 形式版、記事・選択の識別情報/リビジョン、順序写真ID、相対パス、出力日時と保存内容の識別情報が一致する。値をパス命令やシェルとして扱わない。
- **AC1.7.5** Given 処理中、When 重複開始・編集・遅い応答が生じる、Then ジョブの固定内容を変えず二重開始を防ぎ進捗を示す。取得と取消は決めた期限で終端へ収束し、決めた画像メモリ予算を守る。数値はNFR Requirementsで確定する。
- **AC1.7.6** Given 1枚失敗・容量不足・権限喪失・取消・異常終了後の残存一時物、When 終了または復旧する、Then 成功として示さず、当該処理の一時物を片付け、片付け失敗も案内する。下書きと旧成果物を保持して再試行できる。全体完成した場合だけ成功とする。

INVEST：完成した成果物一式の価値でまとまる。画像・保存先・固定入力fixtureで検証可能。8場面で最も大きい見積対象で、画像処理・成果物確定の境界で後続Unitへ分割可能。全場面を最後まで待つのではなく画像1枚の早期実証を先行する。

## US1.8 成果物を見つけてnoteへ手動で移す
本人として、成功した出力フォルダを開いてnoteへ本文と画像を移したい。記事の下書きとして使えることを確かめるため。

対応：FR18、FR12、FR15、NFR7。優先度：Must Have。依存：US1.6のコピー、US1.7の成功成果物。

- **AC1.8.1** Given 成功した出力フォルダ、When 「Finderで開く」を押す、Then 当該フォルダを開く。
- **AC1.8.2** Given 出力後の削除・移動またはFinder表示失敗、When 開く、Then 表示失敗と保存先を案内し、書出し結果と区別する。存在しないものを開いたと表示しない。
- **AC1.8.3** Given コピー可能な本文と出力画像4枚、When 本人がnote編集画面へ本文貼付けと画像挿入をする、Then 写真順・文章の対応を確認した下書きへ手動で移せる。アプリは自動投稿せずmanifestを本文に含めない。
- **AC1.8.4** Given 実画像と本人のMac、When 編集・回転・色・位置情報除去、Sandbox出力、note受渡しを確認する、Then 条件と結果を日本語で記録し、自動試験の成功を本人未確認の成功へ広げない。

INVEST：手動受渡しという独立価値。Finder境界はfixtureで、実際のnote操作は本人確認で検証。外部投稿連携は追加しない。

## 共通品質と依存・検証
NFR1に従い、記事の開始・再開・画像取得・書出しの成功・失敗・取消のいずれでも、写真ライブラリ内の元写真・アルバム・フォルダを変更しない。画像の加工は出力先の成果物に限定する。試験では写真境界の変更APIが呼ばれないことを確認し、本人の実機確認では検証用データの写真・編集内容・アルバム所属・フォルダ構成が処理前後で変わらないことを確認する。通信禁止の確認とは別に判定し、自動試験だけで実写真の非変更を確認済みとは扱わない。

NFR5は全8場面へ適用する。各テスト可能層でTDDを記録し、全製品80%以上と統合前CIを満たす。CI実行先・設定・費用は実装計画で本人確認し、手動試験だけでは統合完了にしない。NFR3の数値はnfr-requirements、NFR4の幅・文字条件はrefined-mockupsで具体化してから実装へ進む。これは要件の免除ではない。

NFR6の通常ログ保護は全場面に適用する。NFR7に従ってXcode中心の起動・確認・戻し方と自動試験コマンドを記録する。VoiceOver追加設計・試験、動画・通知・直接投稿等の除外は維持する。

依存の流れ：既存選択→US1.1→US1.2。US1.3/US1.4/US1.5は下書き状態を使い、US1.6は本文投影、US1.7は固定した保存内容と記事用画像、US1.8は成功成果物とコピーを使う。この順序は説明上の依存で、正式なUnit・実装順序・見積日数ではない。

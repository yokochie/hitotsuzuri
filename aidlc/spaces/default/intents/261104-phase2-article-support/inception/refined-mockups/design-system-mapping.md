# macOS部品と表示方針

## 入力
`../../ideation/rough-mockups/wireframes.md`、同`user-flow.md`、`../user-stories/stories.md`、`../requirements-analysis/requirements.md`、`../practices-discovery/team-practices.md`、本段階確認済み要約を基準とする。既存SwiftUI/AppKitアプリを拡張する。独自デザインシステムや外部UI依存を導入済みとは扱わない。

| 表示・操作 | 使用する標準部品の候補 | 表示上の規則 |
|---|---|---|
| 見出し・本文・状態 | システムフォントとsemantic text styles | 通常文13pt相当、見出し20pt相当を起点とし、OS設定と可読性で検証する |
| 背景・境界 | semantic background、separator | light/darkへ追従。独自の固定色を必須にしない |
| 保存・コピー・出力 | 標準Button、メニュー項目 | 主要操作は「記事と画像を書き出す」。意味をラベルで表し、アイコンだけにしない |
| 本文 | TextField/TextEditor等 | 可視ラベル、複数行、選択/コピー等の標準編集 |
| 日付 | 年月日入力またはDatePicker等の候補 | 年月日を日時と混同しない。入力方式の成立性は実装計画で確認 |
| 下書き選択 | 標準Listとsheet | 行選択と開く/取消、0件・読込失敗を分離 |
| 編集/プレビュー | 標準の分割切替 | 入力を保持し、切替だけで保存しない |
| 保存先 | OS標準フォルダ選択パネル | 本人が選んだ保存先へ限定。Sandbox権限は設計で実証 |
| 進捗・エラー | ProgressViewと可視説明 | 段階が分かる進捗、分からない割合は捏造しない |

## 余白・配置・文字条件
余白16pt、関連要素8pt、領域間16ptを基本にする。記事内容領域640×560pt以上、幅960ptから左右配置。写真列280pt、フォーム最小400pt、プレビュー最大720pt。固定した高さへ文章を押し込み切り捨てない。ボタン列は折返し可。

長名200文字・各本文10,000文字、連続文字・絵文字・改行を検証条件にする。入力上限ではない。200/10,000を超えたデータも黙って切り捨てず、資源等で扱えない場合は理由を示して旧データを保つ。OS標準色の採用をコントラスト実測の合格とは扱わず、実装時に確認する。

## 対象外
新しいブランド色・カスタムアイコンセット・Web用ARIA・モバイル対応を追加しない。VoiceOver追加設計・検証は本人指定で対象外。既存の名称・写真順・保存状態・権限案内の整合を優先する。

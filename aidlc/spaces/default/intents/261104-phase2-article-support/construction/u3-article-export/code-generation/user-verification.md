## Xcodeで起動する
1. `Hitotsuzuri.xcodeproj`をXcodeで開く。schemeを`Hitotsuzuri`、実行先を`My Mac`にする。
2. 通常利用の起動で`--article-test-fixture`や`--ui-test-fixture`を付けない。ユーザーの共有scheme変更は今回書き換えていない。
3. Product → Run（⌘R）で「ひとつづり」を起動する。署名は現在の本人用設定を利用する。自動試験はDebug/macOS宛先・`CODE_SIGN_IDENTITY=-`で実行したもので、公開配布や本番署名の確認ではない。
4. 実装時の測定環境はmacOS27.2（26B123）、Xcode27.2（27B52）、Mac15,3・arm64、AC接続。別の環境で実施したら、その条件も結果へ記す。

## 検証用の写真で一式を確認する
1. 写真アプリでローカル取得済みの検証用4枚を用意する。現在の編集結果、縦横・回転、色、位置情報の有無が分かるものを含める。HEIF/RAW/Live Photoの実際の静止画取得は、それぞれ本人が扱う形式で確認する。
2. Phase1の写真選択を確定し、記事を開く。タイトル、導入、写真ごとの文章、結び、撮影情報を入力する。元写真をアプリで編集する操作はない。
3. 未保存のまま「記事と4枚を出力」を押し、「保存して出力」と「取り消す」の両方を確認する。取消で文章と未保存表示が保たれることを確認する。
4. 保存して出力し、標準パネルで出力先の親フォルダを選ぶ。新しい`記事-…`フォルダに`article.md`、`manifest.json`、`images/01.jpg`〜`04.jpg`が揃うことを確認する。
5. Markdownの画像参照が同じフォルダ内の四枚へ結び、順序と文章が対応することを確認する。manifestの日時はISO8601、形式版は1、画像設定はsRGB/JPEG/品質0.9/長辺2560/非拡大である。
6. 実画像の現在編集・向き・色・寸法を確認し、元のGPS等が不要に複製されていないか確認する。元写真・編集内容・アルバム所属・フォルダ構成が変わっていないことも別に確認する。
7. 同じ記事をもう一度出力し、別フォルダになり前回の成果物が変更されないことを確認する。「画像1枚の検証出力」は別操作で、記事一式の完了とは区別する。

## コピー・Finder・noteへ受け渡す
1. 編集中の本文を変更して「本文をコピー」を押す。貼付け先で現在入力と撮影メモだけが入ることを確認する。コピーで下書き保存済みにはならない。
2. 一式出力後に編集内容を変え、「出力時点の本文をコピー」を押す。完成したジョブの固定本文であり、その後の未保存編集は混ざらないことを確認する。
3. 「Finderで出力フォルダを開く」で当該フォルダを表示する。出力フォルダを自分で移動した場合には、表示失敗が出力失敗と区別されることを確認する。
4. 本人がnote編集画面へ本文を貼り付け、画像01〜04を順に手動挿入する。本文・撮影メモ・画像の順序を確認する。アプリからの直接連携や自動投稿、manifest送信は行わない。

## 取消・確認待ちの扱い
出力中の取消は「受付」と実処理/片付け完了を区別して表示する。処理や確定がまだ不明な場合は成功/取消完了を先に宣言しない。前回の確認待ち記録があれば、同じ親フォルダを選び直して照合する。完成物の照合、または本人が明示した一時物の片付けが終わるまでは新しい一式出力を止める。所有が分からない物や旧完成物をまとめて削除する操作はない。

## 自動試験の再現
リポジトリのルートからU3の機能だけを確認する場合は`bash scripts/verify-article-export.sh --functional`。U3 Coreだけなら`--core`、新規性能2件だけなら本人Macで`--performance`を指定する。正式な全機能/全製品80%の確認は`bash scripts/verify-native.sh --functional`。CIは既存verify.ymlで同じ機能群を実行し、ローカル手動実行とは別に記録する。

## 戻す必要がある場合
アプリを終了し、保存済み下書きと必要な成果物を保持したまま、以前のコミットのアプリを別のチェックアウトからビルドして戻す。既存の選択schemaVersion1と記事保存原本を変更する移行は追加していない。未知版や未完記録を古いアプリで上書き・一括削除せず、必要なら現在のアプリで同じ保存先を再選択して照合する。今回の変更範囲はsource-manifest.jsonに記録している。

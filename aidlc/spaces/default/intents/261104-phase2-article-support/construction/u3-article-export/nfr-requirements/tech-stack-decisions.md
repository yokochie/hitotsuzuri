# U3 技術方針

## Sources
codekb/hitotsuzuri/technology-stack.md、C2/C3、U3機能設計、本人が指定したMac性能/機能CIの分離を基準にする。CodeKBの旧「CI構成なし」は調査時点の記録であり、現在は既存verify.ymlがある。

| 項目 | 方針・理由 |
|---|---|
| アプリ | 既存Swift 6・macOS 27・単一アプリへ組込む。サーバーや別配布単位を作らない |
| 接続 | U1の固定保存入力/画像/保存先とU2の投影/操作ポートを利用し、保存原本を直接書換えない |
| 画像 | 既存Photos/Image I/Oの経路と共有予算を再利用。出力用途を表示キャッシュと分離し、同時一件 |
| 永続化 | Foundationと既存の版付き値・指紋方式を基準にジョブ専用のローカル記録を設計する。記事schemaVersionを無断変更しない |
| 確定と回復 | 同じ選択親内の一時領域から非置換で一括公開。必要な同期/OS排他/実体識別の具体APIと成立性はNFR/Infrastructure設計で検証する |
| OS操作 | 既存の標準保存先選択とアクセス寿命、クリップボード、Finderを薄い境界で実装する。保存先権限の永続化は追加しない |
| 依存 | 新しい外部パッケージ、有料サービス、独自クラウドを追加しない |
| 試験 | XCTestと既存専用runner/正式--functionalを基準とする。先に限定Red/Green、全機能/coverageは完成候補で確認し、長い全体を診断に反復しない |
| CI/性能 | 現行xcode-27の機能CIと全製品80%を維持。実時間/実メモリは本人Macだけで合否判定し、無関係な成功済み測定は反復しない |

現行の本人MacはmacOS27.2/Xcode27.2、直近CIはmacOS27.0.1/Xcode27.1で成功した実績がある。これはU3の未実装成果物の成功証拠ではなく、実装時には実際に用いた環境を改めて記録する。OS全体の認証・TCC・キーボード設定を自動変更して試験を通す方式は採用しない。

# U3 性能・資源の設計目標

## Sources
functional-spec.md BR3.3/3.6/3.7、NFR3、C2/C3。U1の1件画像条件を維持し、四枚一式へ拡張する。全て実装前の目標であり達成済みではない。

| ID | 条件 | 判定 |
|---|---|---|
| NFR3.30 | 高解像度の取得/変換は同時1件。四枚は取得→書込→解放を順次実行し、表示と出力で共有の直接画像バッファ256MiB以下・プロセス増分512MiB以下を守る | 予算予約の単体/競合試験。本人Macで5秒以上のbaseline、50ms以下の実観測間隔、同条件30試行の増分と直接保持を記録。観測条件未成立は合格にしない |
| NFR3.31 | 一枚の画像取得/変換は30秒、書込を含む一枚工程は40秒を上限に新たな処理を許可する。四枚全体はジョブ登録から180秒で新規工程/確定の開始を止める | 単調時計で各工程開始前と結果採用時に判定。180秒は4×40秒と一式検証等20秒の予算。既に確定した結果は成功、確定不明は照合へ移す |
| NFR3.32 | 取消受付の表示0.5秒以下、画像要求の論理終端2秒以下。ファイルI/Oと片付けを含む取消完了を同じ2秒と偽らない | 遅延・逆順・無応答・確定前後の競合試験。正常ローカル保存先では片付け完了まで30試行p95≤5秒を目標。OS I/O停止は未完/照合中を示し、片付け前に取消完了を返さない |
| NFR3.33 | 正常な四枚一式は本人Macで30試行p95≤10秒を目標 | 各4096×3072の合成JPEG四枚、固定本文各10000文字、正常ローカル保存先、画像待機/エラー注入なし。ジョブ登録から一式確定まで計測。これは入力の画素/文字上限ではない |

性能は本人Macでのみ合否判定する。OS/Xcode/機種/電源、対象条件、p95・最大値、各試行、未実施を残す。CIでは決定論的な期限/予算の判定と失敗・取消を検証し、実時間/実メモリのベンチマークを合否にしない。既存U2の無関係な成功済み性能は反復しない。

選択画面での本人待機はジョブ時間へ含めない。OSの停止・スリープ・ファイルシステムが返らない事象で、ネイティブ処理の物理終了時間を保証しない。期限後の新規確定は禁止し、進行中の確定が不明なら同IDで照合する。アクセス/画像資源は実処理が収束してから解放し、未完を完了と表示しない。この成立方式は次段階の設計対象である。

# U1 性能・資源条件

入力は`../functional-design/functional-spec.md`・`rules.md`、`../../../inception/requirements-analysis/requirements.md`、`../../../inception/contract-design/contract-summary.md`と確認済みQ&A。数値は本人承認済みの目標で、実測済みの性能を意味しない。満たせなければ未達として記録し、黙って条件を下げない。

| ID | 対象と判定条件 | 計測 |
|---|---|---|
| NFR3.1 | 画像1枚の取得・変換は開始から30秒以内に成功または理由付き失敗の単一終端。本人の保存先選択待ちを除く | 単調時計、無応答Fakeと実ローカル画像、境界直前/同時/直後を確認。成功を30秒以内に保証する条件ではない |
| NFR3.2 | 変換は同時1件。アプリ直接保持の画像バッファ合計256MiB以内。画像処理前の安定状態からのプロセス実メモリ増分のピーク512MiB以内 | 所有バッファは予約/解放の追跡。プロセスはOS計測で開始前5秒の中央値との差分を50ms以下の間隔で測定。短いピークの見逃しはOSのピーク測定で補完。対象と測定手段はNFR Designで確定 |
| NFR3.3 | 正常な操作可能環境で取消受理表示0.5秒以内、画像要求の論理終端2秒以内。OS残存処理の遅延結果は無効化し、資源解放前に次変換を始めない | 同じプロセスの単調時計。無応答/遅延Fake、実画像の各段階で取消。論理終端とOS資源解放時刻は別記録 |
| NFR3.4 | 正常ローカル保存先で1枚の書込/確定10秒以内、取得/変換を含め40秒以内。ユーザー選択待ちは除く | 十分な空容量と正常権限の保存先。容量不足/読取専用/OS応答停止は失敗または不確定として別計測。期限超過を成功/片付け済みとしない |
| NFR3.5 | 保存・再開の95%を2秒以内。100記事、対象記事1000操作記録、タイトル200文字、導入/4枚各本文/結び各1万文字の試験データ | 本人Macの同一条件で準備後30回以上、開始→確定応答/入力可能の時間。cold起動は別に10回測定し混ぜない。CI計測は参考で本人Mac実測を代用しない |
| NFR4.1 | ファイルI/O・履歴照合・画像処理をUIの同期処理へ載せず、処理中でも無関係な入力/取消が操作可能。主要状態は文字で表示 | UI試験と実機。処理Fakeを停止させ、別入力・取消と状態ラベルを確認 |

画像の試験群は小画像、縦横の高解像度画像、現在編集/回転、HEIF/RAWの取得可能結果、Live Photo静止画、取得不能、極端な寸法、破損を含む。巨大画像を安全に処理できなければcapacity等の失敗とし、512px表示画像や合成画像を成果物として成功にしない。入力の技術的上限が必要ならNFR Designで根拠と失敗動作を明示する。

MiBは1,048,576 bytes。256MiBは追加画像処理経路が直接所有する原画像/中間/出力/圧縮データの合計で、既存表示キャッシュを実証値として流用しない。512MiB増分はOS内部の確保も含めたプロセス測定。上限を観測できない場合は証拠不足であり合格にしない。実現可能なAPIと計測手段を設計段階で確認する。

正常ローカル保存先という前提は、任意の外付け/ネットワーク保存先への成功保証ではない。OS処理停止時もUIを継続し、不確定ジョブを新たな成功/取消完了へ偽装しない。時刻比較は期限と同時なら期限側を優先し、確定点を越えた成功は成功を維持する。

# U1 セキュリティ・データ保護条件

`../functional-design/functional-spec.md`と`rules.md`、`../../../inception/requirements-analysis/requirements.md`、`../../../inception/contract-design/contract-summary.md`を入力とする。単一利用者のローカルアプリで、アカウント/テナント/外部認証サーバーを追加しない。OSの写真許可と利用者選択の保存先を権限境界とする。

| ID | 必須条件 | 合否証拠 |
|---|---|---|
| NFR1.1 | 全画像要求は通信禁止。拒否/削除/iCloudのみ/取消/再試行のどの場合も通信許可へ切替えない | 境界引数の自動検査と本人のオフライン実機確認 |
| NFR1.2 | 元写真・編集内容・アルバム所属・フォルダ構成を変更しない。加工は成果物だけ | 変更APIが呼ばれないFake検査。本人の検証用ライブラリ前後比較。通信禁止とは別判定 |
| NFR2.1 | 旧選択版1を読める。欠損/破損/未知版/権限/I/Oを区別し、未知版を上書きしない | 版/欠損/切断/不正値fixtureと保存後の元byte比較 |
| NFR6.1 | 通常ログに写真・本文・写真ID・人物名・場所を出さない。診断は処理段階/分類中心 | 特徴ある機密テスト値を注入し通常ログを捕捉、含まれないことを検査。必要なユーザー表示はログと分離 |
| NFR6.2 | 下書き/操作記録/manifest/写真を自動送信しない。CIは合成fixtureのみ、秘密情報なし、contents: read | 通信/ログ/CI設定確認。本人ライブラリをCIで参照しない |
| NFR2.2 | 記事保管ルートと利用者選択出力先の外へ、外部ID/タイトル/相対パス/リンクを使って逸脱しない。既存成果物を上書きしない | 空/長名/引用符/Unicode/../絶対パス/リンク/競合の失敗注入。出力ファイル名は内部生成 |
| NFR7.1 | 記事JPEGに位置情報や不要元メタデータを移さず、現在編集/回転・sRGB・品質0.9・長辺2560以下・拡大なし | 出力メタデータ/寸法/色空間の自動検査と本人の実画像確認。元画像との比較条件を記録 |

権限が途中で失われたら依存操作を失敗させ、文章の作業コピーと最後の正常保存を保持する。出力先の文字列だけをアクセス権の証明にせず、選択から全終端までのアクセス寿命を設計する。任意文字列を命令として実行しない。

脅威はローカル保存物の破損/将来版/外部変更、不正ID/パス、遅延応答、誤成功、ログ漏出。独自暗号化/クラウド鍵管理や多利用者認証は追加しない。OSのSandboxとファイル権限を保持する。権限範囲・通常ファイルの保護・署名はInfrastructure Designで確認する。

# U1 保存・取消・復旧の信頼性

`../functional-design/functional-spec.md`・`rules.md`とC1/C2（`../../../inception/contract-design/contract-summary.md`）を具体化する。クラウド稼働率のSLAは対象外。ローカル保存の判定可能性とデータ保護を扱う。

| ID | 必須条件 | 判定 |
|---|---|---|
| NFR2.4 | 保存操作の各中断点で、最後に確定した正常結果または明示的読込失敗へ復帰。途中物を記事にしない。記事結果と操作記録を不可分に確定 | 候補書込/同期/確定参照切替前後の障害注入と再起動。同一操作結果と保存版を照合。未知版/破損を自動修復で消さない |
| NFR2.5 | 同operationID照合は現保存版の競合判定より先。同一入力なら元結果、異入力なら拒否。未確定の新操作だけexpectedRevisionと現在内容を比較 | 成功応答を落とした再試行、後続保存済み後の旧操作再試行、ID異入力、外部変更。二重作成/版増加ゼロ |
| NFR2.6 | 写真なしでも文章/保持済み撮影情報を開き編集/保存。未保存離脱の保存失敗で閉じず、破棄は作業コピーのみ | 権限なし/写真削除/取得不能、保存失敗、終了/切替UI試験。OSコピー完成はU3 |
| NFR2.7 | 画像1枚検証の取消/失敗/期限で旧記事/旧成果物を変更しない。確定前は未成功、確定後は成功を維持。片付け失敗は残存場所付きで報告 | 各段階の取消/容量不足/権限喪失/遅延応答/異常終了後一時物。画像要求の論理終端と出力片付け完了を別確認 |
| NFR5.1 | 各テスト可能層でred-green-refactor、既存回帰維持、全製品の重み付き行カバレッジ80%以上、同一コミットの統合前CI成功 | 変更前baseline、失敗→成功の記録、承認済みbash scripts/verify-native.sh、CI実行URL/commit/結果。手動試験をCIと呼ばない |

上記NFR2.5は機能設計レビューの上流所見（functional-spec R-01）の解決に必要な品質条件。元設計の順序曖昧さを放置せず、NFR Designで優先順序を明示する。出力先未選択時には権限値を持てないという上流所見（entities R-02に相当するレビューの指摘）も、状態別データ型の設計で成立させる。これらは元設計ファイルをレビュー後に無断変更したという意味ではない。

再起動の自動復旧対象は確定記事と識別可能な当該一時物。未保存の強制終了復元、元写真のバックアップ、旧出力画像の自動再利用は対象外。正常保存の証拠がない候補を自動採用しない。OSレベルの原子性・排他・永続化保証の実現は次の設計で確認する。任意外部プログラムの非協調書換えを完全阻止したと約束しない。

障害注入は自動試験で全指定中断点を確認し、実際のアプリ終了/再起動とSandboxは本人確認を分ける。安全性に違反する1件を性能の平均値で相殺しない。

# U1 本人の実機確認手順

## 起動と記事
1. Xcodeで`Hitotsuzuri.xcodeproj`を開き、共有scheme `Hitotsuzuri`、実行先`My Mac`、Debugで起動する。本人の`--measure-native`無効設定は保持済み。通常実行時は合成fixture引数を付けない。
2. 写真の許可を求められたらシステムの画面で許可し、検証用アルバムから4枚を順に選んで確定する。元写真/アルバムを前後比較できる検証用データを使う。
3. 「記事を開く」または「記事」メニューから開始する。最初の骨組み保存後、タイトル・導入・写真1〜4の文章・結びを編集する。撮影情報/日付候補のフォーム完成はU2。
4. 日本語・絵文字・改行・引用符と長文を入力し、Command+Sまたは「保存」を押す。「下書きを保存しました。」と未保存表示が切り替わることを確認する。
5. 編集後に戻る/閉じる/終了を操作し、「保存して閉じる」「変更を破棄」「編集を続ける」を各々確認する。破棄は直前の保存を残す。保存失敗時は閉じず入力を残す。
6. 再起動し、現在の選択の記事、または「記事→保存した下書きを開く」から再開する。写真権限なし/写真取得不能でも本文を再開・保存できることを確認する。同アルバム/同順序の別選択の候補決定はU2へ引継ぎ、U1は無断作成を止める。

## 画像1枚の検証出力
1. 検証用写真の現在編集、縦向き/回転、色、位置情報の有無を写真アプリで確認する。iCloudだけの画像は事前に写真アプリでローカル取得する。
2. ネットワークを切り、「画像1枚の検証出力」またはShift+Command+Eを操作する。未保存なら保存確認が先に出る。
3. OSのパネルで書込可能な専用フォルダを選ぶ。Sandboxはこの選択先へのread-writeだけを追加している。選択取消で写真要求や出力を始めないことを確認する。
4. 「画像1枚の検証出力-内部UUID」に`01.jpg`と照合用`verification.json`が新規生成され、表示先を開いて実画像を確認する。4枚/article.md/manifest/note受渡しの完成はU3。
5. Preview等でJPEG、長辺2560以下、非拡大、向き、sRGB、不要なGPS/元コメントがないことを確認する。写真アプリの原本/編集結果/所属を変更していないことを比較する。HEIF/RAW/Live Photo静止画も取得可能条件を分けて試す。
6. 再出力で旧フォルダが変わらないこと、取得不能/権限取消/容量不足で成功表示にならないことを確認する。「取り消す」は実デコーダの解放と論理終端が別。前処理が残ればbusyを示す。
7. 中断後に確認待ち記録が出たら「前回の出力を照合」で同じ保存先を選び直す。確定済みは内容digestを照合、一時物はjob識別できたものだけ片付ける。識別不能/片付け失敗は表示先を記録し、別jobや既存成果物を削除しない。

## 自動試験と未確認
- 全体: `bash scripts/verify-native.sh`。全製品80%以上とUIを含む。未計測製品ソースの除外なし。
- U1限定: `bash scripts/verify-article-foundation.sh`。各Articleクラスが実行済みでなければ失敗。
- 本人環境macOS27.2/Xcode27.2。現在UI runnerはLocalAuthentication Code=-4「System authentication is running」で初期化不能。OS認証画面の解消後にUIを含む全体を再実行する。実機起動/狭幅/焦点/現在編集と色/Sandbox/アプリcold起動10回は未確認。
- CI workflowは標準xcode-27、読取権限、合成fixtureのみ。公開pushは自動承認レビューで拒否され、CIは未実行。ローカル試験をCI成功とは扱わない。
- OSメモリは5秒基線/25ms観測を実装。lifetime peakが事前fixture由来のrunでは短いピークの帰属が未確認で、完全合格とは扱わない。
- VoiceOver追加確認は本人指定により対象外。

## 戻し方
今回のブランチを統合せず、以前のアプリビルドを使用できる。記事は従来の選択保存と別の`Articles`領域に保存する。戻す前にアプリを終了し、必要な下書き/出力のコピーを保管する。既存の選択データ、写真ライブラリ、完成出力を削除しない。未知版や破損を手動で上書きせず、問題のファイルを保持して確認する。

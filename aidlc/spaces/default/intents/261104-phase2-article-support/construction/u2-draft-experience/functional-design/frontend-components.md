# U2 フロントエンド部品と操作接続

## 構成・正本
本書はfunctional-spec.mdのF2-01〜F2-10を部品へ割り当てる。画面状態と作業コピーは一つの編集セッションに保持し、再配置した部品へ複製しない。永続記事・保存版はC1、写真取得は用途別画像境界、出力/OS操作はC3経由。既存写真選択の状態や焦点を記事部品で上書きしない。

テキスト階層: ArticleEntry/DraftPicker → ArticleScreen（Header、PhotoPreviewList、ArticleForm、MetadataFields、ArticlePreview、ActionBar）。LeaveConfirmationはArticleScreenに対して一つだけ表示する。OutputStatusはU3接続後の結果を表示する境界で、本文の所有者ではない。

## 部品・入力・状態・出力
| 部品 | 入力 | 局所状態 | 外へ渡す操作・保護 |
|---|---|---|---|
| ArticleEntry | 現在選択の可否、既存記事との関連、読込状態 | なし。開始の直列化は画面調整側 | 同じ開始要求。未確定でも保存済み一覧は開ける |
| DraftPicker | 記事ID/タイトル/元名/更新日時の候補、個別失敗 | 選択中の記事ID、一覧内焦点 | IDで開く/新規/取消。未選択の開くは無効、失敗を空へ変換しない |
| ArticleScreen/Header | 編集セッション、元名、保存/日付状態 | 表示モード・焦点はセッションへ保持 | 編集/プレビュー切替、離脱要求。長名は折返し |
| PhotoPreviewList | 順序4ID、番号別取得状態、表示画像 | 表示要求の世代と必要な保持だけ | 番号別再試行。画像失敗でフォームを消さない |
| ArticleForm | タイトル/導入/写真本文4/結びの作業値 | 本文の入力位置。値は作業コピーへ | 入力更新。保存や候補再適用は起こさない |
| MetadataFields | 年月日/候補状態、自由撮影情報 | 日付の年/月/日文字列、欄別検証結果 | 確認/変更/削除。無効文字列を保持し、旧有効日付を投影へ流さない |
| ArticlePreview | 同じ有効な現在入力の投影、番号別表示画像 | 表示位置のみ | 編集へ戻る/コピー要求。値を保存済みにしない |
| ActionBar | dirty/saving/入力妥当性/出力capability | なし | 保存、コピー、出力前保存、戻る。重複操作と未接続操作を制御 |
| LeaveConfirmation | 対象記事の状態、保留した離脱先 | 一つの選択だけ | 保存成功時の離脱/明示破棄/編集継続。Escapeは継続 |
| OutputStatus（操作境界） | 同じjobIDの進捗・終端、成功結果の固定本文 | 応答の世代 | 取消/完了後のOS操作をC3へ。U2単独で成功成果物を捏造しない |

## 表示・配置
幅960pt以上は写真280pt・間16pt・フォーム最小400pt。未満は写真を2列で番号順に置いた縦配置。最小640×560pt、959/960/961ptで切替を検証する。プレビューは最大720pt、左右16pt以上。本文は初期96pt以上の複数行入力、内容に合わせたスクロール。下部操作が本文を覆わず、狭幅で折り返す。名称200文字/各本文10000文字は検証値であり、入力上限へ転用しない。

## キーボードと見えるラベル
本文欄の可視ラベルに写真番号を含める。Tab/Shift-Tabで見た目順に全入力/切替/保存/利用可能なコピー・出力/戻るへ到達し、焦点先を画面内に出す。複数行本文のReturnは改行。Command-Sは記事編集対象にのみ有効。候補一覧は矢印で移動、開くで確定、Escapeは変更なし。確認シートは焦点を内側へ移し、Escapeで編集継続。元画面へ戻ると起点/元入力欄へ焦点を戻す。

保存・候補・エラー・画像取得状態は文字で示す。色だけの区別や画像内だけの番号に依存しない。VoiceOver追加検証は対象外で、既存属性は維持する。

## 主要な操作フロー
1. 開始/下書き選択 → C1読込 → 候補または記事。部分失敗なら正常候補と失敗を併記する。
2. 入力変更 → dirty → 保存時点の写しをC1へ → 成功で基準更新。後続入力があればdirtyを保つ。
3. 日付入力途中/不正 → 欄別説明と入力保持。修正または削除後に有効な保存/投影へ進む。
4. 有効な現在入力 → 記事ID付きの不変投影文脈 → プレビュー/plainText/markdown。モード切替で保存しない。
5. 未保存離脱 → 単一の確認 → 保存成功/明示破棄時だけ準備済み離脱先へ。新対象の準備失敗なら旧編集を保持する。
6. 出力要求 → 必要なら手動保存 → 保存済み固定入力と同じ投影 → C3操作ポート。U3の実装前はFakeで契約を試験し、製品の未接続操作は無効。

## バリデーションとAPI境界
C1に保存済み選択読込・記事照合・一覧・新規・関連付け・保存を依頼する。UIでも日付/4写真対応を検証し、Workspace側の検証を省略しない。許可/破損/未知版/競合/容量/結果不明/I/Oは分類を維持して表示する。写真表示は保存処理の可否条件にしない。

C3のrenderArticleは記事ID付き不変文脈に対する純粋処理。projectIDは選択IDから作らず、元のsource/contentから共通の入力指紋を得る。plainTextは画像/パス/manifestなし。markdownだけが固定4相対参照を持ち、任意入力は文字として表現する。U3に未保存の可変セッションや記事原本への直接書込権を渡さない。

## 状態の採用と試験境界
画面/記事/入力の世代と操作IDを照合し、古い保存成功を新編集の保存済み表示へ使わない。画像は別要求世代、出力はjobIDで識別する。幅変更・再描画・画像到着では日付候補や本文を初期化しない。遅れた書込応答の不採用と、既に確定した保存の結果照合は別に扱う。

C1/画像/C3操作ポートを独立したFakeへ差替え、正常・0件・部分失敗・未知版・競合・保存不確定・連続I/O失敗・遅延・二重操作・日付境界・無効入力・長文・境界幅を確認する。クリップボード/Finder/実画像/Sandbox/手動note受渡しの成功をFakeや画面の存在で代用しない。

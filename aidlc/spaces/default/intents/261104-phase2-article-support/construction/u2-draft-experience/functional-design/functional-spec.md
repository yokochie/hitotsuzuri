# U2 下書き編集と再開の機能仕様

## 入力・担当範囲
本Unitはui。`inception/units-generation/unit-of-work.md`と`unit-of-work-story-map.md`のU2、`inception/user-stories/stories.md`のUS1.1〜US1.7、`requirements-analysis/requirements.md`、`domain-design/components.md`、`contract-design/contract-summary.md`を根拠とする。いずれも同じintentのinception配下。寸法・文字条件は`inception/refined-mockups/mockups.md`・`interaction-spec.md`を引き継ぐ。

本書はUIの操作・状態・入力規則の正本で、独立したentities.md/rules.mdを必要としない。記事正本と保存はArticleWorkspace、未保存編集・焦点・確認はArticlePresentation。保存方式を再実装せずC1を使う。U1の画像1枚検証を四枚出力へ言い換えない。U3のOSコピー・四枚一式・Finder・note手動受渡しは本Unitの完成範囲に含めない。

## F2-01 記事開始・再確定・下書き選択
対応: US1.1（AC1.1.1〜AC1.1.5）、FR1〜FR3。

1. 確定結果の「記事を作る/記事を再開」と記事メニューを同じ開始要求へ接続する。確定選択はC1から読取り、表示画像取得成功を前提にしない。未確定時は現在選択からの開始を無効にし理由を示すが、「下書きを開く」は利用可能。
2. 同時に一つの開始/切替要求だけを受け付ける。読込中の連打や別入口の重複要求で記事を増やさない。
3. 現在の選択IDに結び付いた記事が一つなら再開する。複数なら候補を明示して選ばせ、最初/最新を無断採用しない。
4. 新しい選択IDで同じアルバムID・同じ順序の4IDに候補があれば「新しく記事を作る」「既存の下書きを再開」「キャンセル」。候補が複数なら記事を選んでから再開する。異なる順序は同じ組としない。
5. 新規は別の記事IDを作り、元の選択と既存記事を変更しない。再開はC1のresumeWithSelectionへ操作ID・期待版・新選択を渡し、関連付けだけを追加する。当初のsource、記事ID、本文、撮影情報を保持する。関連付け失敗/不確定時は同じ操作を照合し、成功と断定しない。
6. 下書き一覧は更新日時降順、同時刻は記事ID昇順。タイトル・元アルバム名・更新日時・短い記事識別情報で同名を区別する。空タイトルの「無題の記事」は表示用で、保存値へ書き戻さない。
7. 正常候補と個別読込失敗を別に示す。0件、読込中、全体失敗、正常候補+部分失敗を区別する。失敗項目は開けず、正常候補は改めて読込成功した場合に開ける。読込失敗を「下書きなし」として新規へ流さない。照合範囲が不明な失敗がある間は現在選択からの新規自動開始を止め、再試行/取消を示す。
8. 選択を確定せず閉じた一覧/候補シートは変更なし。シートを入れ子にしない。開いた記事の編集を置き換える場合はF2-04を通す。

## F2-02 編集セッションと保存状態
対応: US1.2（AC1.2.1〜AC1.2.5）、FR4/FR5、C1。

| 保持するもの | 所有・規則 |
|---|---|
| 記事ID、元アルバム名、順序付き4ID、選択来歴 | Workspaceから受け取る。記事画面で写真の並替え/差替えをしない |
| タイトル、導入、写真1〜4の本文、結び、年月日、場所/機材/フィルム/人物名 | 単一の作業コピー。空欄・日本語・結合文字・絵文字・引用符・改行・連続文字を保持 |
| 保存済み基準値、基準保存版、指紋 | 作業コピーと分離。未保存判定は保存済み内容との比較 |
| 入力途中の日付文字列と検証結果 | 画面の作業状態。無効値を旧正常値へ黙って置換しない |
| 表示モード、焦点、スクロール、保留中の離脱先 | セッションに紐付ける。再配置でセッションを作り直さない |
| 保存操作ID、固定した入力、基準値、結果不明状態 | 操作ごとに保持。画像要求や表示切替のIDと共有しない |

手動保存の流れ:
1. 入力を検証する。日付が不正/入力途中ならその欄と修正方法を示して入力を残し、保存しない。空の本文/撮影情報は有効。
2. 保存要求の時点の有効な全入力と基準値を固定し、保存中を表示する。保存ボタンの重複は受け付けない。入力自体は保持し、保存中に新たな入力があれば別の編集として残す。
3. C1の成功応答を受けて初めて保存済み基準値/版を更新する。現在入力が保存した写しと違えば未保存を維持する。入力だけ/プレビュー/コピーでは自動保存しない。
4. 容量/権限/I/O/競合は失敗を文字で示し、現在入力と旧正常保存を保持する。未知版/破損を空として書き換えない。競合は無断マージ/上書きをせず、入力を保持して再読込/編集継続を選べるようにする。再読込で未保存分を失う場合はF2-04を通す。
5. 不確定な保存は元の操作ID・固定入力・基準値を保持し、次の保存で先に照合する。照合中の一時失敗を未確定の証拠にせず、追加入力を元操作へ混ぜない。照合成功後の新入力は新操作として保存する。新操作の確定失敗と、元操作の結果不明を分ける。
6. アプリ再起動後はC1の保存済み本文と撮影情報を復元する。未保存の強制終了復旧は保証しない。旧形式の選択は読込境界を維持する。

| 保存状態 | 見える表示・操作 |
|---|---|
| clean/saved | 保存済み。入力を変更するとdirtyへ |
| dirty | 未保存の変更あり。手動保存可 |
| saving | 保存中。重複保存・離脱の同時実行を抑止 |
| failed | 保存できなかった理由、再試行/編集継続。入力はそのまま |
| uncertain | 保存結果を照合する必要あり。保存済みとも未保存確定とも断定せず、元操作を照合 |

## F2-03 日付候補・初期内容・撮影情報
対応: US1.5（AC1.5.1〜AC1.5.5）、FR8〜FR10。

新規記事の初期化は一度だけ。アルバム名の**絶対末尾**にASCIIの`@`とASCII数字6桁が連続した場合だけ接尾辞として認識する。末尾改行の直前を末尾とは扱わず、空白/改行/Unicode正規化や全角→半角変換はしない。

| 入力名の例 | タイトル候補 | 日付候補 |
|---|---|---|
| `散歩@260913` | `散歩` | 2026-09-13（未確認） |
| `@000229` | 空欄 | 2000-02-29（未確認） |
| `記録@260231` | `記録` | なし。不正な日付として解析結果を案内 |
| `記録@２６０９１３`、`記録@260913追記` | 元名のまま | なし |
| `記録@260913`の後ろに改行がある文字列 | 元名のまま | なし |

候補年は2000+YY、閏年を含む有効なグレゴリオ暦年月日だけを採用する。形式一致した接尾辞は日付の妥当性と独立にタイトル候補から除く。本文各欄と自由撮影情報は空で初期化し、人物/場所/機材等を推測しない。

| 日付状態 | 操作と遷移 |
|---|---|
| absent | 日付なし。手動入力を開始できる |
| candidate | 候補/未確認と明示。確認でconfirmed、変更で未確認を維持、削除でabsent |
| confirmed | 本人の確認済み年月日。手動変更した場合は再び未確認とし、確認操作で確定 |
| 入力途中/invalid（画面状態） | 年/月/日の元の文字列を保持。欄別の説明を表示し、修正/削除で解消する |

手動入力は年1〜9999・月1〜12・その年月の有効日。各欄は半角数字で入力し、不正な文字・範囲・不完全な組合せを自動補正しない。全欄空は日付削除。年月日を保存し、時刻/タイムゾーンへ変換しない。保存/表示/コピーだけでcandidateをconfirmedへ昇格させない。有効な未確認日付はその状態のまま保存できる。

無効な日付のまま保存・本文投影・出力準備はしない。プレビュー切替も修正または削除を案内して編集に留まり、旧正常日付を現在入力の代わりに出さない。その他の文字欄は編集可能で、入力は失わない。

再開した記事では、U1で作成した記事を含め、タイトル/本文/日付/候補状態/自由撮影情報をそのまま使う。新しいアルバム名や候補解析結果を既存記事へ再適用しない。保存済み空欄も本人の状態として保持する。

## F2-04 未保存離脱と対象切替
対応: US1.3（AC1.3.1〜AC1.3.4）、FR6。

離脱先は戻る・ウィンドウを閉じる・アプリ終了・別記事・現在選択からの開始を明示する。確認中は一つの保留先だけを保持し、別要求で無断差替えしない。

| 現在状態/選択 | 結果 |
|---|---|
| cleanで離脱 | 確認なしで移動。新対象の読込失敗はF2-01として案内 |
| dirtyで離脱 | 保存して離れる/保存せず離れる/編集継続の3択。破棄を既定の強調操作にしない |
| 保存して離れる | 保存成功かつその後の追加入力なしでのみ移動。入力不正/失敗/不確定なら残る |
| 保存せず離れる | 明示された未保存分のみを破棄。保存済み記事や選択の正本は消さない |
| 編集継続/Escape/確認取消 | 入力と焦点を保持し、保留先を解除 |
| saving中の離脱 | 結果を待つか編集継続。新しい入力が残れば再判定し、古い成功だけで閉じない |

別記事への切替では、新対象の読込/関連付けが成功して採用するまで旧セッションの作業コピーを保持する。保存せず移る意思を受けても、対象準備が失敗すれば旧編集を残して理由を示す。読込成功前に旧入力を消したり、新規を重ねて作ったりしない。閉じる/終了は実際の完了まで保留し、確認シートは入れ子にしない。

## F2-05 写真表示と文章の独立
対応: US1.4（AC1.4.1〜AC1.4.4）、FR7、NFR1。

記事読込・文章編集・保存・本文投影は表示用写真の完了を待たない。4IDと番号は不変。写真ごとに待ち/取得中/表示可/取得不能を文字と番号で示す。権限なし・参照なし・ローカル未取得・原因不明は判別できる範囲で案内し、不明を具体原因と断定しない。

写真アプリで事前取得してから再試行できる。再試行は新要求とし、現在セッション/写真ID/要求世代に一致する結果だけ採用する。古い結果・離脱後の結果で画像や本文を差し替えない。通信許可へ切り替えず、元ライブラリ変更APIを使わない。表示用画像の成功は四枚の成果物用画像取得の成功ではない。

AC1.4.3の四枚出力の終端と旧成果物保護、出力用画像の再試行はU3。U2はそのポートが返す状態を識別して表示し、表示画像だけで出力成功を決めない。

## F2-06 編集・プレビュー・純粋な本文投影
対応: US1.6（AC1.6.1〜AC1.6.4）、FR11/FR12、C3。

編集/プレビューは同じ作業コピーを参照する。切替で保存、再読込、初期候補の再適用をしない。プレビューは現在入力を、タイトル→導入→写真1/本文1〜写真4/本文4→結び→撮影メモの順で表示する。空欄用の説明や「無題の記事」は表示補助で、本文投影の保存値には混ぜない。note上の最終表示とは保証しない。

本文投影はI/Oのない決定的な処理で、同じ有効な入力からplainText、markdown、順序付き相対画像パス4件とsourceFingerprintを返す。

| 投影要素 | 規則 |
|---|---|
| タイトル/導入/結び | 非空文字列を元の文字と改行のまま使う。自由本文をtrim/正規化しない |
| 写真ブロック | 常に1〜4の順序。プレーンテキストには写真番号と対応本文。画像データ/ローカルパス/manifestを入れない |
| ブロック間 | 構造上の空行を挿入する。各値自身の改行・空白・絵文字・引用符は保持 |
| 撮影メモ | 日付/場所/機材/フィルム/人物名の順。空またはUnicode空白/改行のみの自由撮影項目は省略し、値がある項目の文字列は保持。全項目なしなら見出しも省略 |
| 日付表示 | confirmedは「撮影日：YYYY-MM-DD」、candidateは「撮影日（未確認）：YYYY-MM-DD」。保存やコピーで事実へ昇格させない |
| markdown | 任意入力を文字データとしてエスケープ。HTML/Markdownの注入で画像参照や構造を追加させない。本文の改行は表示上の改行として表現 |
| 画像参照 | markdownにだけ`images/01.jpg`〜`images/04.jpg`を番号順で生成。任意の本文/ID/アルバム名をパスに使わない。ファイルの実在確認と書込はU3 |
| 指紋 | U1の共通規則でsourceと元の有効なcontentから算出する。エスケープ後文字列、保存日時、保存版、記事IDは混ぜない |

### C3の記事識別文脈
C3のrenderArticle入力表はsource/contentを列挙し、出力RenderedArticleにはprojectIDが必要である。元選択IDから記事IDを推定せず、**呼出し対象を記事ID付きの不変な投影文脈**として明示する。この文脈はWorkspaceが既知の記事ID（新規作成中も先に発行したID）から用意する。文脈を固定したrenderArticleはsource/contentだけを受け、同じ文脈と入力から同じ出力を返す。現在の画面を検索する大域状態や、投影時の乱数発行を使わない。

これによりC3の共有値の必須フィールドとsource/content入力形式を維持し、隠れた記事ID依存を明示する。U3はRenderedArticle.projectIDと保存済み入力の記事ID、およびsourceFingerprintを別々に照合する。同じsource/contentから同じ指紋になる別記事を、同じ記事と取り違えない。記事IDがない/不正なら投影を失敗とする。

### コピーと出力前保存
編集/プレビューでコピーする本文は、その操作時点の現在入力を固定して投影する。コピー要求中に後続入力があれば、完了表示は固定した要求の文脈で示し、現在入力を保存済みにしない。別記事/別世代へ遅い成功を表示しない。

U2はcopyPlainText/runExport等の操作ポートの呼出しをFakeで検証する。OSクリップボード/Finderと四枚書込はU3。未接続の製品では未実装操作を成功表示せず、利用不可の操作を無効にする。既存の「画像1枚の検証出力」は別操作名を維持する。

prepareSavedExportは必要なら保存/取消を確認し、保存失敗・不正日付・取消で出力を開始しない。成功した保存内容だけを固定し、その同じ内容を同じ文脈で投影する。保存後の追加入力は出力へ混ぜず、dirtyを消さない。保存先選択前にジョブを開始しない。実行中は対象記事の編集/保存/切替/重複出力を制御し、取消と無関係な操作は応答可能にする。U3へ渡す値以外に記事原本を書き換える権限を渡さない。

## F2-07 画面配置とキーボード
記事内容領域640×560ptを最小とし、横幅960pt以上は写真280pt/間16pt/フォーム、未満はヘッダー→写真2列の番号順→フォーム→撮影情報→操作の縦配置。959/960/961ptの境界で同じセッションを保持する。広幅のフォーム最小400pt、外周16pt、間隔8/16pt。導入/各写真文/結びは初期96pt以上の複数行。プレビュー最大幅720ptで中央、左右16pt以上。

一覧シートは最小480ptで親画面に収まる範囲。名前200文字・各本文10000文字・結合文字/絵文字/改行/連続文字は検証値であり入力上限ではない。内容を切り捨てず、折返し・縦スクロールと操作の折返しで全欄と主要操作に到達させる。既存写真選択画面の切替幅・キー操作を変更しない。

見えるラベルと番号を付け、保存/失敗/取得不能を色だけで示さない。Tab/Shift-Tabは見た目の入力順、Returnは複数行本文の改行。記事編集中のCommand-Sは保存。確認中はシート内へ焦点を閉じ、Escapeは編集継続。候補/一覧の取消は起点へ、記事開始は最初の操作へ戻す。プレビューから編集へ戻れば元の欄と位置を可能な範囲で復元し、焦点先を画面内へスクロールする。VoiceOverの追加仕様・試験は作らず、既存属性の削除も求めない。

## F2-08 画面遷移と非同期応答
| 状態 | 入力/結果 | 次の状態・保護 |
|---|---|---|
| 選択画面 | 記事開始/下書きを開く | 読込中。元選択・旧編集は保持 |
| 読込中 | 正常候補/既存記事/新規可 | 候補選択、記事編集、または明示的新規作成 |
| 読込中 | 全体失敗/部分失敗 | 理由と再試行/取消。空一覧へ偽装しない |
| 候補選択 | 新規/再開/取消 | 生成または関連付けが成功した対象だけ採用/元の画面 |
| 編集 | 文字変更/幅変更 | 同じ作業コピー。文字変更だけdirty、幅変更は保存状態を変えない |
| 編集 | 有効入力でプレビュー | 同じ現在入力のプレビュー。保存なし |
| 編集/プレビュー | 保存/コピー/出力準備 | それぞれの操作IDと固定入力を保持 |
| 編集/プレビュー | 離脱 | cleanなら移動、dirtyなら確認、savingなら直列化 |
| 離脱確認 | 保存成功/明示破棄/継続 | 準備済み離脱先/準備済み離脱先/元の編集 |
| 保存/コピー/画像要求中 | 古い応答 | セッション/対象/要求が一致しなければ表示へ不採用 |
| 出力中（U3接続時） | 完了/失敗/取消 | 同じjobIDだけ採用。固定値を現在入力で置換しない |

保存応答は操作ID・記事ID・セッションID・保存した入力世代、画像応答は要求ID・写真ID・セッション世代、コピー/出力は要求IDまたはjobIDと記事文脈を照合する。採用対象でない応答が来ても、その間に確定した保存の事実を取消済みと偽らない。同じ操作の結果照合を保ち、次の新規作成で二重適用しない。

## F2-09 エラー・境界・非対象
| 境界 | 期待動作 |
|---|---|
| 未確定/不正4ID/順序不整合 | 開始/投影を拒否。元の選択・記事は変更しない |
| 破損/未知版/読込I/O | 分類と再試行。正常記事の一覧と失敗件数を分離し、自動上書きしない |
| 書込容量/権限/競合/不確定 | 作業入力・旧保存を保持。明確な未確定失敗と結果不明の照合を分ける |
| 同名/空タイトル/大量候補 | 記事IDで区別し安定順。スクロール、0件と失敗を区別 |

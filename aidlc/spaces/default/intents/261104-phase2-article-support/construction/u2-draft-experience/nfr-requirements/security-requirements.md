# U2 安全性・入力保護の品質条件

## 入力・信頼境界
`../functional-design/functional-spec.md`、`../../../inception/requirements-analysis/requirements.md`、`../../../inception/contract-design/contract-summary.md`、`aidlc/spaces/default/codekb/hitotsuzuri/technology-stack.md`を根拠とする。本人の単一ローカルmacOSアプリ。アカウント/テナント/API認証を追加しない。OS写真権限とSandboxのファイル権限は別に扱う。個人の写真・文章・撮影情報は画面/必要なローカル成果物以外へ自動送信しない。

## 写真・OS権限
| ID | 条件・判定 |
|---|---|
| NFR1.20 | 記事表示の初回・再試行・期限切れ・取消・許可取消を含む全画像要求で通信禁止。PhotoKit境界Fakeの全呼出しを照合し、実機オフライン確認は別記録 |
| NFR1.21 | 写真ライブラリ変更APIの呼出し0件。取得不能でも文章の編集/保存/有効本文投影ができる。画面の再試行から認可変更・写真編集・ダウンロード命令を代行しない |

既存Sandboxを保持し、U2のために通信権限や広いファイル権限を増やさない。U3の保存先選択/アクセス寿命をU2が肩代わりしない。写真表示成功を出力権限や成果物成功の証拠にしない。

## 永続化・非同期・入力
| ID | 条件・判定 |
|---|---|
| NFR2.20 | schemaVersion 1の旧選択を維持し、記事保存はC1へ委譲。UI導入のためのschema移行なし。未知版/破損/I/Oを空や新規可へ変換せず、正常候補と個別失敗を分離 |
| NFR2.21 | 全編集値・候補状態を単一作業コピーへ保持。保存中の追加入力・不正日付のraw文字列・離脱取消・対象読込失敗でも旧作業値を残す。保存成功で更新する基準値はその操作の固定値のみ |
| NFR2.22 | 保存不確定では元操作ID/固定値/基準版を照合成功まで保持し、照合の一時I/O失敗でクリアしない。競合で無断上書き/マージしない。遅い応答と二重要求をセッション・対象・操作世代で検証 |
| NFR2.23 | 戻る/閉じる/終了/別記事/現在選択開始の未保存確認は一つ。保存失敗・不確定で閉じず、明示破棄だけ未保存を捨てる。切替先準備失敗で旧入力を早期削除しない |
| NFR2.24 | 日付はASCII絶対末尾@6桁と妥当な暦だけ。手動不正値は残して修正案内。新規のみ初期化し、保存/コピー/幅変更/再開で候補を再適用・確認済みに昇格しない |

全条件は正常・空・失敗・遅延・重複・再起動fixtureで検証する。未保存のクラッシュ復旧やバックアップ機能は保証しない。保存済みの耐久性と原子的保存はC1の既存境界を使用し、UIが独自ファイルを書かない。

## データ保護・投影・診断
| ID | 条件・判定 |
|---|---|
| NFR6.20 | 通常ログは操作段階・失敗分類・件数に限定。本文、タイトル、アルバム名、写真ID、人物名、場所、ファイルパス等を記録しない。各失敗経路に識別用canaryを入れ、ログ捕捉で漏えい0件を判定 |
| NFR6.21 | 任意文字は実行せず、Markdown/HTMLの本文として安全に表現。shell/WebView/外部URLの起動に入力を渡さない。Markdown相対参照は固定4件のみ、プレーン本文へ画像データ/ローカルパス/manifestなし |
| NFR6.22 | 記事ID付き不変文脈の投影結果を固定入力に紐付ける。U3は記事IDと指紋を別々に検証。同一source/contentの別記事を同一記事と扱わず、未知/不正IDで投影しない |
| NFR6.23 | 本文コピーは明示操作時点の現在入力、出力準備は保存済み固定値。コピー成功を保存成功へ変換せず、別記事/別世代への遅い成功表示なし。OS未接続は無効表示で、Fake成功を製品成功にしない |

脅威は文章/名称を命令や相対パスにする入力、古い応答による別記事の上書き、ログへの私的情報、未知版の破棄、写真取得権限からの書込拡大。各行の境界検証で防ぎ、一般的な認証基盤や新たな暗号化/規制準拠の保証は追加しない。OSアカウント・ディスク保護は本人環境の前提であり、アプリ独自暗号化を導入済みとはしない。

## 品質証拠・本人確認
| ID | 条件・判定 |
|---|---|
| NFR5.20 | 入力規則/純粋投影、セッション/操作調整、UIの各テスト可能層でred→green→整理を記録。既存回帰を維持し、製品全体の行カバレッジ80%以上と統合前CI成功を要求。製品ソース除外や閾値低下で回避しない |
| NFR5.21 | ローカル成功、CI成功、Fake、実写真、本人確認を分ける。U1で既知のCI失敗は免除やU2合格にせず、統合前に解消/成功を実証する。CI環境変更・費用追加は承認済み範囲を超えて実施しない |
| NFR7.20 | 本人MacのOS/Xcode/署名とXcode起動・確認・戻し方を日本語で記録。狭幅/長文/キーボード/実写真の非変更・通信なしを本人確認項目として残す。未確認は未確認とする |
| NFR7.21 | 編集/回転/色/位置情報除去、Sandbox出力、note貼付けと4枚挿入の実成果物確認はU1/U3と本人の統合確認。U2のFake・UI試験で代替せず、完了条件に所在を残す |

## 信頼性・観測・運用の扱い
サービス用の別個の可用性/拡張性/監視文書はui種別では作らない。保存失敗時の保持と照合はNFR2、応答/資源の計測はperformance-requirements.md、匿名の段階別診断はNFR6、再現と本人確認はNFR5/NFR7に含める。未達は分類・測定条件だけ記録し、常時送信、外部監視、通知、制作履歴画面へ広げない。

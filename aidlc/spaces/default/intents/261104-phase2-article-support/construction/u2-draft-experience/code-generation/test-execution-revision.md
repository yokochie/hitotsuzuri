# U2 検証実行の改訂案

2026-11-05。本人承認 5d3fcfa7、再開 a507c545 に基づく。以下は実施予定であり、スクリプト変更・新しい試験成功・CI成功を意味しない。

## 問題と観測

- 専用実行はCore103件・UI25件成功。UIは1046.958秒。
- 全体実行はCore376件・追加UI25件成功後、既存UIでWindow不在13件、取消1件、未実行18件。共通の起動前提が崩れたまま機能ケースを繰り返した。
- 全体実行中のloading計測359.555秒、長文表示計測265.833秒。両者だけで約10分。性能値の合否を守りつつ、通常回帰と実行を分離する。
- 最新CIは https://github.com/yokochie/hitotsuzuri/actions/runs/41798035585 。nativeと旧版比較baseline-nativeが失敗。U2の現在の変更は未push・未実行。

## 実行順序

1. ビルドとCore試験。UI起動方式ごとに一つの代表ケースを先行実行し、Windowとfixture入口の準備を確認する。
2. 起動確認が失敗した場合、その方式に依存するUI群は実行しない。失敗と未実行を区別し、終了コードは非0。機能不具合や成功として数えない。自動再試行を追加しない。
3. 変更したケースと関連するUI機能回帰を実行する。同一ソースで成功した重い計測は、変更による影響がない限り診断目的で繰り返さない。
4. 公開承認済みブランチへ対象変更をpushし、CIでCore・起動確認・通常UIを実行する。ローカルの全体成功をCI開始の前提にしない。
5. 詳細性能は専用実行として実施。統合対象のソースについて必要な計測が揃った後、全製品の加重行カバレッジ80%以上とCI結果を確認する。部分suiteの値で全体を代用しない。

## ケースと責務

| 対象 | 通常回帰 | 詳細性能・専用実行 |
|---|---|---|
| Coreの入力・暦・関連付け・保存・投影・取消 | 既存376件の機能保証を維持。純粋条件をUIへ重複追加しない | 保存/再開30回、純粋投影100回等、既存の要求回数・閾値を維持 |
| loading表示 | 入口と一覧の表示・取消・完了を代表経路で確認 | testLoadingLabelsThirtyEntryAndListRequests の各30回を専用群へ |
| 長文入力と表示 | 長文の保持、保存、編集/preview切替、写真取得/保存中の入力を残す | testLongDraftNativeDisplayPerformance の反復計測を専用群へ |
| cold起動 | fixture方式ごとの起動確認 | testApplicationColdInputReadyTenLaunches の10プロセスを専用群へ |
| キーボード・閉鎖・候補・再開・幅境界 | 実UIに固有の保証として残す。既存NativeInputTestsを一括除外しない | 640/959/960/961/1200の境界と長文を必要な変更時に再確認 |

削除・統合はケース名と保証するAC/NFRの対応を確認して決める。現時点では機能ケースの削除や性能サンプル数の削減を承認済みの変更と見なさない。高さ560ptの自動計測不足も未解消として残す。

## 変更する範囲と確認

- 専用/正式スクリプトに起動確認と機能/性能の明示的な実行区分を設ける。無引数の正式検証は必要な全区分を含み、失敗・未実行の検出を維持する。
- 同一xcresultに含まれない区分のカバレッジは、正当な集計方法を確認する。単純な率の平均や都合のよいbundleの選別は禁止。必要なら正式全体検証を最終一回だけ残す。
- 旧fixtureの復元状態隔離は仮説として一つの代表ケースで確認する。OS設定変更や失敗アサーションの弱化はしない。
- CIの通常回帰と詳細性能を区分し、どちらの結果も追跡可能にする。30分制限への適合と失敗時の結果保持を確認する。費用/権限/公開範囲を広げない。
- U1ブランチ限定の旧版比較ジョブは診断用。過去の失敗を現在製品の成功条件に混ぜず、無断で無効化しない。

スクリプト改訂前に承認済みcode-generation-planとunit-test-instructionsへこの順序・変更対象を反映する。追加の実行モードや起動前提確認自体は、意図した失敗と成功を短い範囲で検証する。

# CI性能の設計

## Context
入力は `../nfr-requirements/performance-requirements.md`。成功PRの既存run 42321598795、42254722121、42254356001のActions開始から必須job完了までの参考値はそれぞれ29:27、31:58、33:40。PR更新時刻との対応および環境差は別途照合する。
run 42321598795では機能ジョブ27:58、機能UI 78件の合計25:05。ArticleDraftUITestsが7:03、NativeInputTestsが6:03、ArticlePhotoRestorationUITestsが4:50。30%には参考中央値で約9分35秒の短縮が必要で、Coreジョブの短縮だけでは届かない。
出典: https://github.com/yokochie/hitotsuzuri/actions/runs/42321598795/job/128247663346

## Decision
まず上位のUIケースをログの時刻順に読み、アプリ起動、fixture準備、画面状態待ち、操作、終了・回収を区別する。操作が可能になったことを確認できる場合に限り、固定待ちや連続する代替待ちを条件待ちに置き換える。独立したケースの状態と検証条件を維持し、各変更の所要時間と試験結果を記録する。最初に小さい変更で測定し、有効なパターンだけを広げる。

## Alternatives Considered
- ビルド再利用はビルド区間に十分な短縮余地があると分かれば検証する。単一のCI実行内で完結させる候補とし、別runの成果物共有は初期案に含めない。
- UIの分割実行は短縮候補。独立したGUI環境、実行枠、失敗時の挙動、80%カバレッジ算出の同等性が成立する場合に別途設計する。

## Consequences
所要時間の内訳は1 runの証拠。具体的な変更箇所、見込める削減量、比較可能な標本の確定は実装前に行う。PR更新から全必須チェック完了の中央値で30%を判定する。

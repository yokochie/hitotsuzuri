# CIの保護設計

`../nfr-requirements/security-requirements.md`を設計へ反映する。
- 既存のcontents読取、checkout認証情報非保持、Actionsのコミット固定を構成差分で確認する。PRのテキストを実行コードに渡さない。
- UIのfixtureは合成データとケース固有の所有領域を使う。再利用案では素材の準備と試験中に変更する保存領域を分離する。ログは結果・所要時間・識別子を対象とする。
- 初期案は既存のrunnerと実行ごとの作業領域で完結させる。成果物共有を後で検討する場合は、書込主体・読取主体・commit/ツールチェーン照合を設計し、信頼できないPRからの混入を防ぐ。

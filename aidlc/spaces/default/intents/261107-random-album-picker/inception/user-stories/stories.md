# アルバムのランダム選択 ユーザーストーリー

## US1.1 一覧からアルバムを抽選する

記事用の写真を選ぶ本人として、今の一覧から1回の操作でアルバムを選びたい。どのアルバムから写真を探すかを自分で決める手間を減らせる。

**優先度** Must Have。**対応要件** FR1、FR2、NFR1。**依存** 既存のアルバム一覧と手動選択の経路。

- **AC1.1.1** 一覧にA・Bがあり、一覧外にCがあり、Aを開いているとき、抽選するとAとBが同じ確率で選ばれる。スクロールで画面外にある行も候補に含まれ、Cは選ばれない。
- **AC1.1.2** 一覧が空のときは抽選できず、1件だけのときに抽選するとその1件が選ばれる。
- **AC1.1.3** 確定前の写真を選んでいるとき、開いているアルバムが当たっても写真一覧と選択は保たれる。
- **AC1.1.4** 抽選して当選アルバムを開くとき、システム写真ライブラリへの書き込みや画像取得のための通信要求は発生しない。

## US1.2 写真を選択中の切り替えを確認する

記事用の写真を選ぶ本人として、別のアルバムが当たったときに切り替えるか決めたい。選びかけの写真を意図せず失わずに済む。

**優先度** Must Have。**対応要件** FR3。**依存** US1.1の抽選結果。各分岐は当選結果を固定して個別に検証できる。

- **AC1.2.1** Aで写真を選択中にBが当たったときは、確認を表示し、返答まではAと写真選択を保つ。
- **AC1.2.2** 切り替えを承諾するとBが選ばれ、写真一覧がBに切り替わり、Aの確定前の選択が解除される。
- **AC1.2.3** 切り替えを取り消すと、Aの写真一覧と確定前の選択を保つ。
- **AC1.2.4** 確定前の選択が空のときにBが当たると、そのままBに切り替わる。

## US1.3 狭いウィンドウで当選した行を確認する

記事用の写真を選ぶ本人として、狭いウィンドウで抽選した後もアルバム一覧を見ていたい。画面が切り替わらず、どの行が当たったかをその場で確認できる。

**優先度** Must Have。**対応要件** FR4。**依存** US1.1の当選確定。表示結果は選択状態を固定して個別に検証できる。

- **AC1.3.1** 狭いウィンドウでアルバム一覧を表示しているとき、Bの当選が確定すると、一覧にとどまりBの行を選択済みとして示す。
- **AC1.3.2** 広いウィンドウでBの当選が確定すると、既存の写真領域にBの写真を表示する。

## 検証

3本とも1つの利用者価値を扱い、受け入れ条件ごとに検証する。操作名やボタンの位置は実装計画で決める。NFR2は3本共通の検証条件として扱い、既存CIと製品全体の行カバレッジ80%以上を確認する。本人の写真ライブラリでの操作確認は自動試験と別に記録する。

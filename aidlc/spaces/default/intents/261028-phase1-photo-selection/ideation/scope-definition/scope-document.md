# ひとつづり Phase 1 — 範囲定義

## 入力と決定の根拠

- [目的の文書](../intent-capture/intent-statement.md): 本人の写真活動で、後の記事・動画制作に使う4枚を選んで保持する。
- [成立性評価](../feasibility/feasibility-assessment.md): 条件付きで実現可能。実ライブラリ参照と画像取得の早期確認が必要。
- [制約一覧](../feasibility/constraint-register.md): 本人のMac、システム写真ライブラリ1つ、ライブラリ変更処理なし、画像取得通信なし。
- [確認済み回答](scope-definition-questions.md): 復元を含め、自動追従・手動更新・一覧の付加機能を後回しとする範囲、および確認順序。

## 目的と最小の利用価値

本人が写真アプリ内の複数フォルダから対象アルバムを見つけ、1アルバムの中から順序付きで4枚を選択・確定・保存できる。次回起動時には対象フォルダと最後に確定した4枚を復元できる。参照が無効な場合は確定済みとして扱わず案内する。

## 今回含める範囲

| ID | 利用者ができること・必要な保護 | 優先度 | 根拠 |
|---|---|---|---|
| S-01 | 写真アクセスの目的を理解し、許可する。拒否・制限時は案内を受ける | Must | 目的の文書・成立性評価R-01 |
| S-02 | 写真アプリのフォルダ階層を見て複数フォルダを対象にする | Must | 目的の文書 |
| S-03 | 選択フォルダ以下の入れ子のアルバムを探す。重なる探索結果に同じアルバムがあっても重複表示しない | Must | 目的の文書・成立性評価F-02・リスクR-03 |
| S-04 | アルバムを1つ選び、写真選択用サムネイルで写真を閲覧する | Must | 目的の文書・確認回答Q4 |
| S-05 | 選択順を確認しながら最大4枚を選び、解除する。4枚のときだけ確定する | Must | 目的の文書・確認済み要約 |
| S-06 | 確定時に参照の有効性を確認し、4枚の識別子と順序をローカルに保存する。検証・保存失敗を成功として表示しない | Must | 目的の文書・確認回答Q2 |
| S-07 | 次回起動時に対象フォルダと最後に確定した4枚を復元する。無効な参照は確定扱いにせず案内する | Must | 確認回答Q1 |
| S-08 | 空状態・取得失敗・無効な選択・保存失敗の案内を受ける | Must | 成立性評価・確認回答Q1/Q2 |
| S-09 | 本人のMacで100枚以上のアルバムを使った性能確認を行う | Must | 確認回答Q3 |
| S-10 | Swift・Xcodeの経験を前提としない日本語の実行・検証手順を利用する | Must | 制約一覧C-07 |

写真枚数・検索・代表画像を省く判断は、写真を選ぶためのサムネイル表示を省く判断ではない。深い階層や親子フォルダを含む確認データ、写真の種類や並び順、画像が取得できない場合の扱いなどの詳細はInceptionで要件化する。

## 今回含めない範囲

| 機能 | 扱い・理由 | 根拠 |
|---|---|---|
| 起動中のライブラリ変更の自動反映 | 後回し。変更は再起動で読み直す | 確認回答Q2 |
| ライブラリの手動更新 | 後回し。確定時の検証・失敗案内は今回行う | 確認回答Q2 |
| アルバム名検索・一覧の写真枚数・アルバム代表サムネイル | 後回し。中核の探索・選択・保存を優先 | 確認回答Q4 |
| note連携・記事生成・動画生成・SNS投稿 | 後続フェーズ | 目的の文書 |
| クラウド機能・同期・毎週の自動実行と通知 | 対象外 | 目的の文書 |
| 写真本体の恒久複製・履歴管理 | 対象外。保持するのは最後に確定した選択 | 目的の文書・確認回答Q1 |
| 複数ライブラリファイルやFinderフォルダの直接選択 | 対象外。システム写真ライブラリ1つに限定 | 制約一覧C-02 |
| 画像取得のための通信 | 行わない | 制約一覧C-05 |
| 配布方法の確定・配布公開 | 後で決める。まずローカル実行を完成させる | 目的の文書 |

## 完了判断と確認方法

| 観点 | 今回の完了判断 | 確認方法の方向 |
|---|---|---|
| 探索 | 複数フォルダと入れ子のアルバムを取得し、重複なく選べる | テスト用データと実ライブラリの両方 |
| 4枚選択 | 順序と解除が正しく、5枚目を追加できず、4枚未満では確定できない | 自動テストと画面操作 |
| 保存と復元 | 確定した識別子と順序を保持し、再起動後に有効な選択を復元できる | 自動テストと再起動確認 |
| 変更・削除 | 画面が即時追従しなくても、確定時に無効な参照を成功として保存しない。再起動で読み直せる | 削除・無効化のテストと実機確認 |
| 性能 | 本人のMacで100枚以上を対象に、読み込み中の操作とメモリ使用を確認する | 数値基準と測定手順はInceptionで確定 |
| データ保護 | ライブラリを変更せず、アプリから画像取得通信を要求しない | コード確認と実機確認 |

## 作業順序と依存関係

実ライブラリへのアクセス・フォルダ取得・ローカル画像取得の不確実性を先に確認する。その後、閲覧と4枚選択、確定・保存、再起動復元へ積み上げる。性能・失敗時の安全性・日本語手順は対応する作業と一緒に確認する。固定の期限はない。

利用価値の流れ（テキスト表現）: 許可する → フォルダを選ぶ → アルバムを探す → 写真を見て4枚を選ぶ → 有効性を確認して確定・保存する → 次回に復元する。

## Inceptionに残す判断

- 保存先・形式と、保存失敗時の扱い、復元時の一部欠損・アルバム外への移動の扱い。
- ローカルにある写真の判定、表示用画像が取得できない写真の選択・確定可否。
- 選択解除後の順序、アルバム・フォルダ変更時の選択状態、写真の種類・並び順。
- 性能の具体的な基準と測定手順、最低macOSと実行確認対象。
- 受け入れ条件を実装単位・依存関係・テストへ対応づける計画。

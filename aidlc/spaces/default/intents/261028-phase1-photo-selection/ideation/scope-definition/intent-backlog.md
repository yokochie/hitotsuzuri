# ひとつづり Phase 1 — 優先順位付き作業一覧

## 根拠と読み方

入力は[目的の文書](../intent-capture/intent-statement.md)、[成立性評価](../feasibility/feasibility-assessment.md)、[制約一覧](../feasibility/constraint-register.md)。範囲は[範囲定義](scope-document.md)、本人の優先順位は[確認済み回答](scope-definition-questions.md)による。

MoSCoWを用い、今回の完成に必要なものをMust、今回入れないものをWon'tとする。利用者数・作業量に実測根拠がないため、RICE等の数値は作らない。以下は能力単位の候補であり、Inceptionで確定する実装単位ではない。

## 依存関係と検証順序

B-01 → B-02 → B-03 → B-04 → B-05。B-06は各能力に随伴する。実ライブラリ参照とローカル画像取得を先に確認するという本人の選択を尊重し、取得の不成立が後段の選択・保存へ波及する前に明らかにする。

テスト用データでの自動確認も必要だが、実写真へのアクセス許可や実際の画像所在を代替するものとはしない。本人による実機確認が必要な箇所を各実装単位の計画に明記する。

## 要件・計画への引継ぎ

各S-IDを要件・受け入れ条件に展開し、実装単位と検証へ対応づける。今回の範囲承認は、未決定の詳細要件・技術選定・実装計画やConstructionの開始を承認するものではない。

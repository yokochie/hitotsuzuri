# ひとつづり Phase 1 — リスク・前提・課題・依存関係

上流資料: [目的の文書](../intent-capture/intent-statement.md)。評価根拠: [確認回答](feasibility-questions.md)、[成立性評価](feasibility-assessment.md)、[検証記録](evidence/verification.md)。優先度は定性的な判断であり、発生確率の実測値ではない。

## Risks

| ID | リスク | 優先度 | 対応・完了条件 | 担当 |
|---|---|---|---|---|
| R-01 | 権限や署名設定により実ライブラリを読めない | 高 | 早期に署名済みアプリで許可・拒否とフォルダ取得を実機確認する | 実装担当・本人 |
| R-02 | メタデータはあるが画像がローカル取得できない | 高 | 通信を許可せず、失敗・空画像の状態を区別する。確定可否は要件分析で決定する | 要件・実装担当・本人 |
| R-03 | 実フォルダ構造や親子同時選択でアルバムの欠落・重複が出る | 高 | 深い階層・親子選択・同名異ID・空フォルダをFakeと実ライブラリで検証する | 実装担当・本人 |
| R-04 | 選択後の削除やアクセス変更で無効な参照を保存する | 高 | 確定時の検証と失敗時の扱いを要件化。変更追従を省く場合も失敗時の安全性を確保する | 要件・実装担当 |
| R-05 | サムネイル要求や同期取得でUIが停止する | 中 | 性能の最低条件をInceptionで決め、対象Macと写真枚数を記録して実測する | 要件・実装担当・本人 |
| R-06 | 参考コードをそのまま採用してコンパイルできない | 中 | 既知のinout捕捉エラーを採用しない。残りの認可・監視・並行処理を実装時に検証する | 実装担当 |
| R-07 | コンパイル成功を実行互換性の保証と取り違える | 中 | 最低OS候補と実際に動作確認したOSを別々に記録する | 設計・検証担当 |

## Assumptions

| ID | 未検証の前提 | 確認方法・期限 | 担当 |
|---|---|---|---|
| A-01 | 本人のシステム写真ライブラリに、対象の写真フォルダと写真が存在する | 最初の実機確認で対象フォルダの表示を確認する | 本人 |
| A-02 | 画像取得通信を要求せずに、利用したい写真の表示用画像を取得できる | ローカル写真と取得不能写真を分けて実機確認する | 本人・実装担当 |

## Issues

| ID | 課題 | 状態・次の対応 |
|---|---|---|
| I-01 | 設計案の再帰探索はinout引数をescapingクロージャで捕捉する | コンパイル失敗を再現。代替走査のコンパイルは成功。製品への反映と動作テストはConstructionで行う |
| I-02 | 最低OSと保存・復元・変更対応・性能の詳細範囲が未決定 | Scope DefinitionとRequirements Analysisで整理し、要件と計画の確認を受ける |
| I-03 | 実機での認可・フォルダ取得をまだ確認していない | 最初の動く実装単位で本人の確認を必要とする |
| I-04 | Swiftマクロの型チェックが制限環境では起動できなかった | 制限外で検証専用コードをコンパイルし成功。写真へのアクセス・コードの実行はなし。ビルド時にも同様の制約が発生する可能性を記録 |

## Dependencies

| ID | 依存先 | 必要なこと |
|---|---|---|
| D-01 | 本人のMac・Xcode・macOS SDK | コンパイル環境は確認済み。署名・権限を含む実行確認は未実施 |
| D-02 | macOS Photosと本人の許可 | 対象ライブラリ、写真フォルダ、ローカル画像へのアクセス |
| D-03 | 本人の意思決定と実機確認 | 要件・計画承認、許可ダイアログへの応答、結果の共有 |
| D-04 | ローカル保存領域 | 保存先・形式はInceptionで決定。保存失敗時の振る舞いを要件化 |

## 次段階への引継ぎ

未確定事項を採用済み要件と扱わない。AWSの実行基盤は今回の依存先に含めない。PhotoKit・PhotosのOS側の挙動や画像の所在は、検証コードのコンパイルだけでは保証できない。

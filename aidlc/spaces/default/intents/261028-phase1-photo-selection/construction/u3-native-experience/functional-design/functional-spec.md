# U3 画面・操作支援・性能の機能仕様

## 根拠と責務

[実装単位](../../../inception/units-generation/unit-of-work.md)、[割当](../../../inception/units-generation/unit-of-work-story-map.md)、[ストーリー](../../../inception/user-stories/stories.md)、[要件](../../../inception/requirements-analysis/requirements.md)、[構成要素](../../../inception/domain-design/components.md)、[契約](../../../inception/contract-design/contract-summary.md)に基づく。
US1.1〜US1.8の表示・操作支援・性能を担当する。[承認済み操作仕様](../../../inception/refined-mockups/interaction-spec.md)と[チェックリスト](../../../inception/refined-mockups/accessibility-checklist.md)を引き継ぐ。UI単位のため本書が操作と状態遷移の正本。永続モデルと4枚ルールの所有者を増やさない。[CI省略](../../../change-decisions/2026-10-31-local-verification.md)を適用し、統合前ローカル検証と全製品80%以上を維持する。

## F31 領域と移動

通常はフォルダ・アルバム・写真の3領域と写真下部の4枠を表示する。820pt以下では表示領域を切り替え、最小640×560ptで4枠・状態文・確定操作に到達できる。領域切替で編集状態や展開状態を初期化しない。元の領域へ戻ると存在する直前の操作対象へフォーカスを戻し、消えた場合は領域見出しまたは最初の操作可能対象へ移す。非同期画像完了だけではフォーカスを奪わない。
長い名称は省略しても全名のヒントと読み上げを提供。同名異IDを独立して操作し、フォルダの展開と複数選択を分離する。未選択・空・読込中・失敗はそれぞれ説明する。

## F32 キーボードの主フロー

1. 許可説明と許可ボタンへ到達し、本人の操作で許可要求を行う。
2. フォルダ一覧で上下移動、左右で階層展開、標準の複数選択により対象を選ぶ。
3. アルバム一覧で対象を選び写真領域へ移る。同一アルバムの再選択では選択を保持する。
4. 写真を矢印で移動、Spaceで選択/解除する。列数変更後も同じIDを基準に位置を保つ。Tabで領域を退出できる。
5. 下部4枠・枚数を確認し、確定または再試行へ移る。全経路で可視フォーカスを提供する。

取得不可写真は選択操作を実行せず、識別と理由はフォーカスまたは読み上げから確認可能にする。5枚目は追加せず既存順序とフォーカスを保ち、4枚上限を文言で伝える。解除後の順番詰め・再選択末尾は進行担当の結果を表示する。ドラッグ並べ替えを追加しない。

## F33 画像・選択・読み上げ

写真ラベルはアルバム内位置と利用可能な識別情報を使い、存在しない日時を創作しない。選択状態と選択順1〜4、取得状況を意味として提供し、番号・枠・文言で色以外にも伝える。下部4枠は同じID/画像参照を使う実画像プレビューで、未選択枠は空枠とする。各枠は順序と写真識別を読み上げ可能にする。
VoiceOverで領域名・フォルダの展開/選択・アルバムの選択・写真の順番・枚数・保存結果へ到達する。状態の更新を読み取れるようにし、画像応答ごとの過剰な通知を避ける。

## F34 保存・復元・回復の表示

復元中と検証/保存中は編集と重複確定を無効化し理由を示す。保存終了で操作可能に戻し、元の操作位置を維持する。保存失敗時の再試行は本人の操作だけで行い、参照/画像を再検証する。参照不正や画像不可は準備と再起動を案内する。設定保存と4枚確定の状態を混同しない。未保存変更、保存済み、復元成功、欠損全解除、保存なし、破損、未知版を区別する。

C4の置換成功後はその結果を保存済みの根拠とし、その直後の権限変化や呼出し取消で「未保存の失敗」へ変換しない。操作ID・固定内容の照合と現在権限の案内を分離する。保存成功と同時に権限喪失があれば、新しい確定の写しと成功結果を保持した上で、写真参照ができない案内を併記する。保存自体が失敗なら以前の確定と編集を保持する。この契約の是正には進行担当の変更を伴うが、C4の成功の意味や権限の安全条件は変えない。

## F35 表示資源と性能

見えている写真と選択4枚を必要集合とし、外れた表示要求を取消し、保持参照を解放する。表示領域切替・スクロール・アルバム変更後に古い応答を採用しない。全生存画像と予約256MiB、要求最大8（通常4/検証4）、512物理pixel、画像1件/全4枚の各15秒期限を維持する。画像取得通信は要求しない。
100枚以上の実アルバムで30回以上の選択/解除を入力イベントから実際の画面反映まで測り、95%以上200ms以内を確認する。10回往復後の資源安定と不要要求0を15秒以内に確認する。詳細の計測器と記録形式はNFR設計へ渡す。内部状態の更新時間だけで合格としない。

## 遷移と検証

| 事象 | 表示と操作 |
|---|---|
| 領域切替/幅変更 | IDを保持し適切な対象へフォーカス復帰 |
| 選択/解除 | 枚数・番号・4枠・読み上げ意味を同じ状態から更新 |
| 5枚目/画像不可 | 選択不変、理由を確認可能 |
| 保存/復元中 | 進行表示、編集を拒否 |
| 保存成功と権限喪失の競合 | 新確定と成功結果を保持、権限不足は別案内 |
| 保存失敗 | 編集と旧確定保持、明示再試行 |
| 復元1件無効 | 全写真解除、有効フォルダ保持、理由案内 |

状態・幅・入力境界は自動テスト、実キーボード/VoiceOver・コントラスト・画面反映性能・実Photosは本人確認と分離する。新しい画面構成案の承認は要求せず既承認モックに従う。未確認は合格と記録しない。

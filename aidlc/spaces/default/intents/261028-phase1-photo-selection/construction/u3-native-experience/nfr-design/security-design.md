# U3 保護と保存結果の設計

根拠: [性能と操作支援](../nfr-requirements/performance-requirements.md)、[保護](../nfr-requirements/security-requirements.md)、[技術](../nfr-requirements/tech-stack-decisions.md)、[機能仕様](../functional-design/functional-spec.md)、[契約](../../../inception/contract-design/contract-summary.md)。以下は実装前の設計であり、未測定を合格としない。

## S31 境界を維持

NFR3.31、NFR3.33。表示担当はC1だけを操作し、写真ライブラリや保存先を直接変更しない。画像はネットワークfalseを維持し、不可でも通信へ切り替えない。原本保護と明示的な破損回復、未知版/過大/symlink拒否は既存回帰を維持する。表示用の画像を恒久複製しない。

## S32 成功結果と認可の分離

NFR3.32。検証と保存開始前は現在の認可・操作ID/世代・固定内容を確認する。保存開始後は保存担当の実完了結果を待ち、成功なら操作IDと固定内容の整合に基づいて新確定を反映する。完了直後の認可不足や呼出し取消を再検査して成功を失敗へ変換しない。
認可が失われたなら保存成功とは別の参照不可状態として案内する。保存担当が本当に失敗した場合だけ保存失敗とし、旧確定と編集を保持する。結果未確定で二重書込みしない。保存中に操作IDが入れ替わらない制御を維持し、成功結果を捨ててディスクと写しが食い違う経路を作らない。権限喪失と取消が正常完了へ競合する回帰を先に書き、ディスク・写し・保存状態を照合する。

## S33 診断と検証

NFR5.31〜5.33。通常ログは最小失敗分類だけ。任意の測定は連番・時間・件数・bytesのみを採取し、個人ID・名称・画像・原本を出さない。画面フレームは本人が許可した測定の一時的な照合に限定する。外部監視・アップロードを追加しない。TDDと全製品80%以上をローカルで検証し、実機未確認は別表へ残す。

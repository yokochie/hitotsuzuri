# U3 テスト手順

## 構成

既存XCTestを使い、hostlessのHitotsuzuriU3Testsを共有schemeへ追加する。外部依存は追加しない。Step2でrunnerを実行確認してから各層のRedへ進む。

## U3専用コマンド

```bash
xcodebuild -project Hitotsuzuri.xcodeproj -scheme Hitotsuzuri -destination 'platform=macOS' -only-testing:HitotsuzuriU3Tests -enableCodeCoverage YES -derivedDataPath .build/DerivedData CODE_SIGN_IDENTITY=- test
```

各Redは意図した失敗を記録し、その後にGreenと整理を行う。XCTest起動権限等の環境失敗をRedとしない。

## 範囲とテストデータ

U3SaveCompletionTests、U3LayoutTests、U3FocusTests、U3AccessibilityTests、U3ResourceTests、U3MeasurementTestsとU3IntegrationTestsで責務ごと5〜8件を基準に正常系/2件以上の境界を検証する。目安を上限にしない。
Fakeのライブラリ/画像/保存、注入時計、合成の名称/ID/画像を使用する。個人の写真やApplication Supportへ書き込まない。UI構造/描画を検証し、実VoiceOverや実画面性能の本人確認とは区別する。測定判定は入力時刻/フレーム時刻/番号の合成データで再現し、実測の成功としない。

## カバレッジ

全製品Swiftの加重行80%以上を維持。U3専用実行だけで全体閾値を判定せず、Build and Testで全単位の組合せ結果を既存計測器へ渡す。UI・実アダプタ・App入口を分母から外さず、全既存108件を回帰確認する。統合前ローカル検証は本人承認のCI省略決定に従う。

## 再実装の回帰

測定入口とモデルの不変操作拒否をU3MeasurementTests、実選択の前後とフレーム照合をU3IntegrationTestsへ追加する。既存の同じU3専用コマンドを先に確認し、実Redを記録してから修正する。正常な選択/解除と、5枚目/取得不可/凍結/無効IDを区別する。初回解除や元の状態へ戻る有効な操作を誤って除外しない。全159件を含む回帰と全製品80%以上は全体実行で確認する。

## Loop-back 2 の実UI試験

HitotsuzuriUITestsを既存Xcode/XCUITestで構成する。Debug限定 --ui-test-fixture 起動で合成の親子フォルダ・複数アルバム・画像・メモリ内保存を使い、実Photos許可や個人データを操作しない。最初に以下の正確なコマンドが実行可能であることを確認してから、左右キー・Command複数選択・写真キーボード選択の実入力Redを記録する。

```bash
xcodebuild -project Hitotsuzuri.xcodeproj -scheme Hitotsuzuri -destination 'platform=macOS' -only-testing:HitotsuzuriUITests -enableCodeCoverage YES -derivedDataPath .build/DerivedData CODE_SIGN_IDENTITY=- test
```

各UIテストはアプリを起動し、キー/マウス修飾入力から表示結果を確認する。内部のモデルやtoggleFromUIを直接呼ぶ試験は既存の下層回帰として維持するが、上記3操作の成立証拠に代用しない。OSのUI試験実行許可が不足する場合は未実行理由を残し、自動で許可を与えない。試験に含める画面は合成データだけとする。

全製品80%以上は既存U1/U2/U3と新規UIテストの組合せ結果で判定する。Debug fixtureの製品側コードも一律に除外しない。新規verify-native.shの最終指定は本人確認後に行い、既存verify-all.shは変更しない。

## Loop-back 3 のTab停止先回帰（計画・本人承認待ち）

本人報告3fc70abcの3操作成功を保持し、操作不能な静的見出しへのTab停止だけを修正する。承認前には実装・試験実行しない。承認後、上記の正確なUI単位コマンドでrunnerを確認してから、実入力Red→Green→Refactorを進める。UI起動時の通常幅復帰を保ち、個人Photosや保存領域を使わない。

- Tab/Shift+Tabの実キーイベントごとのAXフォーカス先を観測する。領域見出しと静的trayが停止先にならないこと、操作可能な要素では実際に操作できることを確認する。取得不能な焦点情報を成功へ読み替えない。必要な観測補助はテスト側を優先し、私的SDKや業務モデル直接呼出しで回避しない。
- 通常幅/狭幅で領域間を前進・逆進する。空のアルバム/写真領域への切替・復帰でも静的文字や存在しない行へ焦点を強制せず、操作可能な移動先または自然な退出となることを確認する。
- 写真0〜3枚で確定が無効な場合と、4枚で有効な場合を分ける。写真からTab退出・Shift+Tab復帰ができ、静的「選んだ写真」に止まらず、Spaceの二重選択や焦点の閉じ込めがないことを表示結果で確認する。
- 見出しのVoiceOver header属性・領域名を保持する。自動AX属性確認と実VoiceOver利用者確認は別に記録する。実写真の基本操作と3操作の既存本人成功を維持し、非表示子フォルダ選択の受入済み保留問題には変更しない。

現在の基準は `.build/Native-20261102-224338-54127.xcresult` の184件成功・失敗0・スキップ0、全製品89.29%。追加回帰後は、承認済みの次のコマンドで全体を再確認する。既存assertionや閾値を弱めず、製品の分母からUIを除外しない。

```bash

```

## 本人追加要求のTab入場回帰（新計画・本人承認待ち）

- 通常幅/狭幅、逆Tab再入、空一覧、保存等での凍結を区別する。空一覧では何も選ばず、初回表示・マウスだけの入場・遅延データ到着をTab起因と取り違えない。必要な合成条件はDebug専用とし、空一覧を作るために実Photosや本人データを変更しない。

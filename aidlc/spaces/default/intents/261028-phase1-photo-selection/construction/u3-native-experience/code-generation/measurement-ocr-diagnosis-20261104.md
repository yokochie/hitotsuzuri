# 測定OCRの単一フレーム診断

代理実機測定ではcapture起動と30回の実操作後のseq30表示を確認したが、ツール結果は操作数0・対応0・不成立83で未確認だった。これは性能未達の証明でも合格でもなく、入力と表示フレームを対応付けられていない結果である。

コード確認では、HZM2のprefix発見、厳密な書式解析、seqの連続性、同一フレームのHZC/HZS完全一致の各段階が同じ不成立数へ集約されていた。最初のseq1をOCRで採用できない場合、後続seqも連番条件で拒否される。空白結合・O/0認識などの具体的な発生原因は未確定である。

`scripts/measure-native.swift`へ`--diagnose`を追加した。既存captureと同じ起動・許可確認・対象ウィンドウ・Vision設定を使い、最初の完全フレーム1枚のみOCRし停止する（待機上限10秒）。画像やOCR全文、写真名は保存・出力しない。表示は既知測定prefixの候補数、token数、数値解析可否、O/o数、解析済みの連番・選択位置、HZC/HZS数値、同一frame完全一致に限る。診断ではseq30なども観測できるが、測定入力へ採用せず合否を出さない。既存のseq1始点、欠測拒否、同一frame照合、実表示時刻、30操作・95%・200msの条件は変更していない。

本人または親がリポジトリ直下で実行するコマンド：

```sh
env DYLD_FRAMEWORK_PATH=.build/DerivedData/Build/Products/Debug .build/measure-native --diagnose
```

親の初回診断ではHZM2はseq30・前[1]・後[]で解析成功、HZSの1件とHZCが非数値、同frame完全一致falseだった。この結果を受け、期待token数が合うHZS/HZCに限定して非数値欄のUnicode符号位置（最大8scalar）とscalar数を追加した。文字の置換や許容拡大は行っていない。

Swift 6で既存Core frameworkをリンクし`.build/measure-native`を再ビルド、終了0・診断なしを確認した。作業担当は`--diagnose`・`--capture`を実行していない。追加診断と原因確定は親の実行待ち。アプリ製品コード、判定Core、OS設定、Photosには変更なし。今回の変更は本スクリプトと本記録のみで凍結する。

## 追加診断に基づく数値欄の最小補正

親の再診断でHZS slot1の値欄とHZC count欄の非数値はどちらもU+00F8だった。画面上のSF Monoの斜線zeroをVisionがøと誤認したことが原因と確認された。本人要求により、測定prefixが正確にHZM2/HZS/HZCである場合の数値欄だけ、観測済みのøをASCII 0へ補正する共通関数を追加した。captureとdiagnoseの両経路で用いる。補正後もASCII数字だけであること、token数と文法、HZS slot1〜4、HZC count0〜4、位置の整数範囲、HZM2の有効な前後遷移を確認する。O/o、任意の英字、prefixや数値欄以外は補正しない。

raw診断の非数値符号位置は維持し、末尾に数値正規化後の同一frame完全一致を追加した。観測を採用する連番、前後状態の連続性、欠測拒否、実表示時刻、同一frame照合、95%/200ms条件は変更していない。

再ビルドは終了0。画面を使わない自己試験を実行した：

```sh
env DYLD_FRAMEWORK_PATH=.build/DerivedData/Build/Products/Debug .build/measure-native --self-test
```

結果は「マーカー数値正規化自己試験: 21件成功（画面取得なし）」、終了0。正常ASCII、既知ø、不正英字、誤prefix、範囲外、token欠落・過剰、無効な遷移、整数overflow、符号や全角数字の拒否を含む。workerは実画面取得を行っていない。親による`--diagnose`の同frame一致と、その後必要に応じたseq0からの再測定は未確認である。今回の追記とスクリプトを再凍結する。

## 採用フレームの時間内訳

親がø補正後の同frame診断trueを確認し、seq0から30回のcaptureで入力30・対応30・不成立0を得た。ただし200ms以内は0で未達だった。この試行はCUAクリック保持700msを含むため、入力時刻から表示までの時間に保持時間が含まれる可能性を残す。既存の結果を保持し、親が短いクリックと別の操作間隔で再測定する。

切分け用にsummaryへ各seqの`upperMs`、`deltaMs`（入力から対応フレームの表示時刻まで）、`intervalMs`（上限へ加算した直前フレーム間隔）を追加した。既存ledgerが採用したフレームだけ、すでに受け取ったmach ticksとtimebaseから診断値を計算する。採否・上限時間の計算式・判定閾値・連番規則は変更していない。出力は連番と時間数値のみで、写真名・識別子・画像を含まない。

再ビルド終了0。`--self-test`は数値正規化21件と時間換算内訳1件が成功、終了0。時間換算試験はnumer125/denom3でdelta100ms、interval約16.666667msを確認した。workerの画面取得は未実行。新内訳を用いた実測と性能達成は親の確認待ち。スクリプトと本記録を凍結する。

# U2 本人による確認

## 準備

XcodeでHitotsuzuri.xcodeprojを開き、Hitotsuzuri schemeと本人のMacを選び実行する。写真アクセスを求められた場合は画面の説明から本人が許可する。自動テストではこの操作と実ライブラリを確認していない。

正常JSONはアプリのSandbox内Application Support/Hitotsuzuriに保存する。通常のFinderでの場所は ~/Library/Containers/com.yokochie.Hitotsuzuri/Data/Library/Application Support/Hitotsuzuri/。settings.jsonは対象フォルダ、selection.jsonは最後の確定。画像本体は保存しない。quarantineは破損原本の保護領域で、選択履歴ではない。

## 確認項目

すべて現時点で**本人未確認**。各項目の確認日と結果を追記する。

- [ ] 正常: 対象フォルダを複数選択し、アルバムから任意の4枚を順番に確定。終了して起動し直し、対象フォルダ・アルバム・4枚・順序が一致し、復元成功の文言と4枠の画像を確認する。
- [ ] 未保存: 確定後に選択を変更して終了。再起動時は変更前の最後の確定4枚が戻ることを確認する。
- [ ] 外部変更: 専用のテスト写真/アルバムを使い、保存した1枚を写真アプリ側でアルバムから外して再起動する。4枚全体と編集中アルバムが空になり、有効フォルダが残ることを確認する。写真そのものを削除する確認は、本人が削除してよいテスト用コピーで行う。保存原本は自動消去されない。
- [ ] 対象外/アルバム削除: テストアルバムの構成を変更し再起動。部分復元せず、再起動や選び直しの案内になることを確認する。
- [ ] 権限: システム設定の「プライバシーとセキュリティ」内の「写真」で本人が許可を変更し、再起動する。拒否時は参照を進めず、保存原本を維持して権限を案内することを確認する。許可を戻したら再起動する。
- [ ] 取得不可: ローカル画像が取得できないテスト写真で、通信を要求せず、成功復元とならず、写真アプリで準備後の再起動案内になることを確認する。
- [ ] 書込失敗と回復: 専用保存領域を別の安全な場所へコピーし、アプリ終了後、検証用の保存先だけ一時的に書込不可にして再起動・確定する。失敗時に旧確定と編集が保持されることを確認し、書込権限を元へ戻して「保存を再試行」。成功後にのみ確定を更新する。個人領域全体の権限を変えない。

## 破損/未知版の手動復旧

アプリを終了し、専用保存領域全体をコピーして原本とquarantineを保管する。自動削除はしない。

selection.jsonだけが破損している場合は、起動しただけでは変更しない。対象を確認して有効な新しい4枚を明示的に確定すると、原本の同一bytesをquarantine/selection-<SHA256>.jsonへ保護してから置換する。退避不可/内容不一致/原本変更/置換失敗では成功としない。書込環境を直した後、本人が再試行する。

settings.jsonの破損は自動修復しない。アプリ終了・保存領域のコピー保管後に、本人が破損settings.jsonを保存領域の外へ移してから起動し、対象フォルダを選び直す。移動した原本を消さない。設定と確定は別レコードなので、selection.jsonまで移す必要はない。

未知版は対応するアプリを確認する。旧アプリで上書きを試みない。1 MiB超過や読取不能も自動回復の対象外。安全なコピーと原因確認を先に行い、元データを保護する。quarantineファイルやJSONには個人の参照が含まれるため、Gitや検証記録に内容を貼り付けない。

## 自動確認との境界

Fakeと隔離JSONで正常・失敗・退避・再試行を確認済み。実Photosの権限、写真アプリの並び、実画像、保存先の環境は上記本人確認が必要。U3の最終操作支援と性能測定は別に行う。

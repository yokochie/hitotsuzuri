# U1 テスト実行手順

## 対象と前提

本人のMac、Xcode27.2/Swift6.4.2、macOS27.2 arm64を観測済み。Xcodeプロジェクトと共有schemeをStep1で用意し、製品の実装より先にホスト不要のXCTestターゲットHitotsuzuriU1Testsを実行できる状態にする。外部パッケージは追加しない。テストターゲット名はU1専用であり、後続単位のテストを含めない。

## 単位専用の実行コマンド

作業ディレクトリはリポジトリのルート。

```sh
xcodebuild -project Hitotsuzuri.xcodeproj -scheme Hitotsuzuri -destination 'platform=macOS' -only-testing:HitotsuzuriU1Tests -enableCodeCoverage YES -derivedDataPath .build/DerivedData CODE_SIGN_IDENTITY=- test
```

この正確な単位フィルターをRed/Green/Refactorで使う。起動準備の失敗・署名設定失敗・テスト未発見を、期待したRedに数えない。Xcode由来の出力は.build/DerivedData配下、実行の失敗/成功と件数は実装記録へ残す。署名はローカルad-hoc。対象Macでビルドが成立しなければ修正してから最初のRedへ進む。

## テスト構成

| 所有責務 | 件数の目安 | 検証 |
|---|---|---|
| LibraryAccess | 5〜8 | 認可、深い階層、重複/循環、同名異ID、順序、参照無効 |
| ImageAccess | 5〜8 | 通信false、最終/暫定、期限、取消、世代、予算/同時数 |
| SelectionPersistence | 5〜8 | 正常往復、失敗保護、未知版/破損、サイズ、直列化 |
| SelectionWorkflow | 5〜8 | 4枚境界、切替、入力固定、再検証、失敗保持 |
| PickerPresentation | 5〜8 | 状態投影、枠/番号/枚数、確定可否と案内 |
| 結合 | 3以上 | 許可から保存読戻し、参照削除、保存失敗 |

総数35〜45件を目安とし、必要な境界を満たすための増加は許容する。数合わせの常時成功テストは作らない。モデルの境界は各責務のテストへ加える。

## Fake・データ・隔離

認可と階層/画像APIをFakeにし、注入時計で15秒の境界と遅延順を制御する。画像はテスト内で作る小さな合成画像のみ。保存試験は実行ごとの専用一時ディレクトリで行い、正常な旧内容を用意して失敗を注入する。テスト用ディレクトリだけを後処理し、本人の通常保存先と実写真へ触れない。

## カバレッジと統合前検証

行カバレッジ80%以上は製品全体の条件。U1テストだけの実行は選択テストの成否を判定し、後続単位のソースが増えた後の全体カバレッジを代替しない。Build and Testでは全単位のテストを組み合わせ、製品アプリとCoreの全手書きSwiftソースを分母として判定する。U1だけの段階でも統合前に全製品ソースの80%以上を確認する。実アダプターやViewの一律除外・閾値引下げはしない。

scripts/verify-u1.shは上記単位専用コマンドとU1結果の検査をラップする予定。カバレッジはXcode結果の実行行数/実行可能行数を重み付き集計し、ファイル率の単純平均を使わない。スクリプトの具体的な最終検証呼出しは、生成後・初回単位検証前に本人へ確認する。カバレッジだけで非ゼロの場合は全選択テスト成功との区別を記録し、合格扱いせず不足を補う。

CIは本人の変更承認により不要。ローカル検証を実行していない試験をCI予定として済ませない。実機確認は日本語手順で本人が行い、結果未入力を成功にしない。

# U1 容量と並行性の要件

根拠: [機能仕様](../functional-design/functional-spec.md)、[業務ルール](../functional-design/rules.md)、[要件](../../../inception/requirements-analysis/requirements.md)、[内部契約](../../../inception/contract-design/contract-summary.md)、[確認回答](nfr-requirements-questions.md)。以下は受け入れ条件であり、測定・実装済みとの主張ではない。

## 要件

| ID | 条件 | 判定 |
|---|---|---|
| NFR2.7 | 2フォルダ以上・3階層以上、100枚以上の写真を受け入れ用データとする。固定の全件切捨てを設けない | Fakeと本人の実データで確認。100枚は最大件数ではなく検証の下限 |
| NFR2.8 | 階層探索は訪問済みIDを管理し、同じフォルダ/アルバムの重複と循環を打ち切る。UIの画像要求は必要な範囲へ限定する | 深い階層・親子重複・同名異ID・循環・遅延を自動テスト |
| NFR2.9 | 確定保存の同時実行は最大1件。画像要求は有限の同時数と有限の保持予算で制御 | 重複確定と高速切替のテスト。同時数の具体値はNFR Designで決定 |

## 容量計画

利用者1名・システム写真ライブラリ1つ・単一の編集セッションを設計単位とする。複数ウィンドウで独立編集を増やさず、画面は同一セッションを参照する。拡張トリガーは100枚以上の実データでの性能未達・保持上限への到達・実階層での処理不能であり、先に要求サイズと資源寿命を修正する。上限値の変更が必要なら本人へ根拠を示す。クラウドの水平拡張や複数利用者の容量目標は非該当。

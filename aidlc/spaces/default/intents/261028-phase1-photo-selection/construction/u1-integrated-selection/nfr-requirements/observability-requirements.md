# U1 診断と検証記録

> 2026-10-31 本人承認による変更: 今回のPhase 1ではCIを省き、統合前のローカルビルド・自動テスト・行カバレッジ80%以上を必須とする。本文のCI実行・専用Mac・ランナー準備に関する旧条件は適用しない。TDD・本人の実機確認は維持する。[変更記録](../../../change-decisions/2026-10-31-local-verification.md)。


根拠: [機能仕様](../functional-design/functional-spec.md)、[業務ルール](../functional-design/rules.md)、[要件](../../../inception/requirements-analysis/requirements.md)、[内部契約](../../../inception/contract-design/contract-summary.md)、[確認回答](nfr-requirements-questions.md)。以下は受け入れ条件であり、測定・実装済みとの主張ではない。

## 要件

| ID | 条件 | 判定 |
|---|---|---|
| NFR5.1 | 通常は失敗の分類のみを診断へ記録し、操作履歴を常時蓄積しない | ログ捕捉で写真ID・名称・画像・低水準エラー文字列を除外確認 |
| NFR5.2 | 検証時だけ入力から画面反映までの経過時間・要求開始/完了/取消数・現在の不要要求数・画像保持推定量を一時計測 | ローカル計測。持続時間には単調時計を使う。通常の製品ログから性能達成を推定しない |
| NFR5.3 | TDDの意図した失敗と成功、対象と除外根拠を含む行カバレッジ80%以上、統合前CIを各単位で記録 | 未実施・実行不能・失敗・成功を区別。対象は製品Swiftソース全体を基本とし、自動生成コード以外の除外は根拠を計画で明示し基準を下げない |
| NFR5.4 | 許可・写真アプリの並び・実画像・画面・操作支援は本人の実機確認欄へ記録 | 日本語のXcode中心手順。実画像や個人IDを成果物へ転載せず、確認条件と結果だけを残す |
| NFR5.5 | 具体的な検証コマンドは最初の実装単位の検証前に本人確認し、未承認の例を承認済みとして扱わない | 検証の承認記録と実行結果を対応づける |

## 指標と案内

画面反映率は200ms以内の操作数/対象操作総数（30以上）、画像保持は256 MiB以下、不要要求は最後の移動後15秒以内に0。条件と測定方法を併記する。閾値未達を検証結果で失敗として報告し、勝手に閾値を上げない。クラウド監視・外部ダッシュボード・アラート送信は設けない。通常診断はOSの標準ローカルログの管理へ委ね、アプリ独自の永続診断ファイルを追加しない。一時計測の生データは検証セッション内だけ保持し、必要な匿名集計値だけMarkdownへ記録する。

# U1 信頼性要件

根拠: [機能仕様](../functional-design/functional-spec.md)、[業務ルール](../functional-design/rules.md)、[要件](../../../inception/requirements-analysis/requirements.md)、[内部契約](../../../inception/contract-design/contract-summary.md)、[確認回答](nfr-requirements-questions.md)。以下は受け入れ条件であり、測定・実装済みとの主張ではない。

## 要件

| ID | 条件 | 判定 |
|---|---|---|
| NFR3.6 | 保存の成功は固定内容が専用領域へ置換完了した場合のみ。設定と確定は別レコードで、書込みは直列化 | 成功・ディスク書込失敗・中断を注入し、旧正常内容または新しい正常内容が残り、半端な内容を正常扱いしない |
| NFR3.7 | 書込み失敗で旧確定と編集を失わず、本人の再試行時は再検証する。結果未確定の保存を二重に開始しない | 遅延・重複・失敗・古い操作IDのテスト。画像の15秒を保存の打切りに流用しない |
| NFR3.8 | 破損・未知版・読込失敗を保存なしと同一扱いにしない。未知版書込は禁止し原本を保持 | 破損・欠損フィールド・未対応版・I/O失敗を自動テスト。U1では危険な上書きを拒否、退避して再確定する回復経路はU2 |
| NFR3.9 | 起動・設定変更・参照欠損だけで旧確定を自動破棄/上書きしない。復元時の全写真クリアと有効フォルダ保持はU2で完成 | U1の書込境界テストとU2の正常/欠損復元テスト |
| NFR4.1 | 取得中・空・取得不可・原因不明・保存失敗を区別し、次の操作を日本語で案内する | U1は基本表示、U3でキーボードとVoiceOver・長い名称・狭幅を完成 |

## 保証の範囲

常時稼働サービスではないため月間稼働率のSLAやクラウド災害復旧時間を追加しない。電源断・媒体故障を含むゼロ損失は約束しない。アプリ起因の半端な置換と誤った成功を防ぎ、起動時には保存形式を検査する。バックアップは写真本体の複製機能として追加しない。破損原本の退避はU2の回復操作のための限定的な保存データ保護として技術設計する。

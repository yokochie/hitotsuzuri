# U1 性能要件

根拠: [機能仕様](../functional-design/functional-spec.md)、[業務ルール](../functional-design/rules.md)、[要件](../../../inception/requirements-analysis/requirements.md)、[内部契約](../../../inception/contract-design/contract-summary.md)、[確認回答](nfr-requirements-questions.md)。以下は受け入れ条件であり、測定・実装済みとの主張ではない。

## 要件

| ID | 条件 | 判定方法・担当 |
|---|---|---|
| NFR2.1 | 画像取得完了後の選択・解除は入力イベントから表示反映まで、30操作以上の95%以上が200ms以内 | 本人のMac・100枚以上のローカル写真。計測器・記録手順をNFR Designで決定しU3で実測。Store更新時間で代用しない |
| NFR2.2 | ローカル画像1要求は受付から15秒以内に最終成功・取得不可・失敗・取消のいずれかへ収束 | 仮想時計による境界・遅延テストと実機確認。暫定プレビューで時間を延長しない |
| NFR2.3 | 確定前4枚の画像検証全体は開始から15秒以内。1件ごとの15秒を足して60秒にはしない | 4件の成功・一部停止・期限ちょうどの競合テスト。単調時計の期限以降の応答は不採用 |
| NFR2.4 | アプリ所有のデコード済み表示画像は推定256 MiB以下。一覧・4枠・検証画像を含む | 実バッファの推定byte数を一元集計し超過前に解放・要求制御。同一バッファの重複参照は二重計上せず、別コピーは計上。OS内部・プロセス全体のメモリは別記録 |
| NFR2.5 | 100枚以上で10往復スクロール後も保持量は上限以下、不要要求が残り続けない | U3で実測。最終スクロール後15秒以内に不要要求0を確認。画像API内部の保持量をアプリ側と混同しない |
| NFR2.6 | 探索・画像処理・ファイルI/OでUIを不必要に止めない。取得中も依存しない操作が可能 | 非同期境界・取消・古い応答を自動検証。保存中の編集禁止は意図した制約。初期読込の固定時間保証は設けず、件数と経過時間を測定する |

## 単位の寄与

U1で世代照合・取消・解放・保持予算と期限の基礎を実装する。NFR2.1とNFR2.5の最終受け入れ測定はU3に残す。上限を通すため写真を勝手に欠落させたり、通信を許可したりしない。具体的な画像サイズ・同時要求数・待機キュー制御は次の技術設計で上記条件を満たすよう決める。認可ダイアログと保存完了待ちは画像の15秒対象外。

# U1 統合前ローカル検証と実行手順

根拠: [性能設計](../nfr-design/performance-design.md)、[保護設計](../nfr-design/security-design.md)、[容量設計](../nfr-design/scalability-design.md)、[信頼性設計](../nfr-design/reliability-design.md)、[診断設計](../nfr-design/observability-design.md)、[論理構成](../nfr-design/logical-components.md)、[構成要素](../../../inception/domain-design/components.md)、[機能仕様](../functional-design/functional-spec.md)、[内部契約](../../../inception/contract-design/contract-summary.md)、[CI省略の決定](../../../change-decisions/2026-10-31-local-verification.md)、[確認回答](infrastructure-design-questions.md)。設計であり環境設定・製品ビルド・自動テストの実施結果ではない。

## CIを省く決定

ファイル名は成果物契約に従うが、CIランナー・CIワークフロー・自動配置を設計しない。以前の専用Mac CIと統合前CIの条件は本人の明示承認で撤回済み。今回のintentでは以下のローカル検証を統合前必須とする。別作業のチーム既定を一括変更するものではない。

## 実装から統合まで

1. mainを起点に短い作業ブランチを用い、対象Unitのコード・テスト・日本語手順を計画する。TDDで意図した失敗を確認し、最小実装で成功させ整理する。
2. Xcode共有schemeで製品をビルドし、Fakeと専用保存先を使う単体/統合テストを実行する。写真権限の要求や本人の通常保存先への書込を自動テストに含めない。
3. 製品Swiftソース全体を基本に行カバレッジ80%以上を確認する。除外は生成コード等の根拠を明示し、単体ロジックだけの値を製品全体としない。
4. 許可・階層・手動並び・ローカル画像・選択・保存を本人がXcodeで起動して確認する。U1の統合成立性を設計の合格で代替しない。
5. コミットID・ツールチェーン・実行内容・合否・カバレッジ対象・本人確認結果を記録する。記録の対象ソースを変更した場合は影響する検証を再実行する。
6. 必須の検証が成功した変更をまとめてmainへ統合する。失敗・未実施なら統合しない。フェーズ終了時のGitコミット指示も維持する。

## 段階と確認条件

| 段階 | 必須条件 | 証拠 |
|---|---|---|
| 実装計画 | 対象ファイル・TDD・テストと除外根拠 | 承認されたコード生成計画 |
| ローカル検証 | ビルド成功・自動テスト成功・行カバレッジ80%以上 | 対象コミットとXcode結果 |
| 最初の一通り動く実装 | 写真アクセスから4枚確定保存まで本人が確認 | 日本語の実機確認欄 |
| U2/U3 | 各単位の変更後にローカル検証、単位固有の実機確認 | 同じ条件で記録 |
| 統合 | 上記に失敗・未確認の必須項目なし | 検証済みの内容へ対応したコミット |

## コマンド・署名・成果物

具体的な検証コマンドはコード構成を確定してから、最初の実装単位の検証前に本人確認する。ここに承認済みコマンドの仮置きをしない。UIでのXcode操作手順と、再現可能な自動検証の実行手順を分ける。ローカル署名とSandbox・写真権限を含むアプリ起動を対象Macで確認する。証明書の購入・外部公開・公証・アカウント登録を自動で進めない。

ビルド成果物はローカルに置く。秘密情報・個人写真・写真ID一覧・個人の保存JSONをGitへ含めず、テストデータだけを管理する。GitHubの非公開状態は確認済みだが、リモートへのpushやPR作成・公開は本書の作成では行っていない。

## 戻す手順

失敗時はmainへ未統合の変更を修正し再検証する。既存作業を消すreset/cleanを手順にしない。統合済みコードを戻す必要がある場合は対象コミットを特定して変更を取り消す計画を作り、専用保存データは自動削除しない。保存版の変更を伴う場合は旧アプリの読込可否を確認してから戻す。CI停止・クラウド資源削除の作業は存在しない。
